# Sweep Corpus

The health checks fire only when something schedules them; this skill is the schedule, running the doc-claim check, the lint gate, and the cross-reference check over this repo. It **reports and never edits `src/`**: the fix for a finding is a normal session's work, landed through review.

Its writes are one new `docs/health/<date>.md` per run plus the one additive `docs/health/open-findings.md` — two files on the first run, one more on every run after. Both are **tracked**, because `open-findings.md` carries findings across sessions and must survive a clone; `.gitignore` therefore does not name them, and `git add -A :/` in any tree stamp will pick them up. So a sweep starts from a clean tree — § 3 says why — and its own output is the only thing standing in the working tree when it ends, landing as **its own commit** rather than riding someone else's: the repo's `Landing:` block pre-authorizes push but not commit, so the sweep ends by asking for that commit. A sweep asked for over a change in flight refuses rather than stamping a tree the checks did not read.

## Workflow

### 1. Refuse while a finding is open

Read `docs/health/open-findings.md` (create it on the first run: the `# Open findings` heading, the additive legend, an empty `## Open`, and an empty `## Closed` for step 2 of § Closing a finding to move rows into). A finding still listed as open stops the sweep: report the open finding and exit. Refreshing the open list over an unfixed finding is how a sweep becomes a log nobody reads.

The gate is lifted only by § Closing a finding below, which runs **outside a sweep**. Nothing in this workflow clears the open list — step 3 appends to it — so a sweep that refuses here stays refused until a fix session closes the row by hand. That is the intended shape, not a deadlock, and § Closing a finding is the entry point a reader arriving at this refusal is owed.

### 2. Run the family

- `bash -c 'for g in scripts/lint-skills.sh scripts/lint-adrs.sh scripts/*-selftest.sh scripts/git-hooks/*-selftest.sh global/hooks/*-selftest.sh .claude/skills/*/scripts/*-selftest.sh; do case "$g" in *"*"*) echo "no gate matched $g"; continue;; esac; [ -f "$g" ] || { echo "FAIL $g is named by this loop and is not there"; continue; }; echo "== $g"; bash "$g"; echo "exit=$?"; done'` — the mechanical gate. **Every gate that exits non-zero has its output carried into the report verbatim**, because a restated failure is the sweep grading the gate rather than reporting it; a run where all of them exit 0 is reported as one table of `exit=` values, since there is no failure text left to lose. **Run it under `bash`, not the login shell**: under zsh an unmatched glob is a fatal error and the loop never runs, so the gate reports nothing and reads as silence rather than as failure. Every self-test under `scripts/`, `scripts/git-hooks/`, `global/hooks/`, and `.claude/skills/*/scripts/` runs here, derived by the `<script>-selftest.sh` pairing rather than named by hand (the same derivation `scripts/git-hooks/post-merge` makes): a gate nobody runs degrades exactly as silently as no gate. That is why the two miss branches say so rather than continuing quietly, and say so **differently**: an unmatched glob comes back as the literal pattern, which is `no gate matched` — expected for a tree that holds none of that kind, a finding only when one should be there — while a **named** gate that is not on disk is a `FAIL`, a linter renamed away with this loop left pointing at the old name. One word for both cannot tell the expected empty from the broken pointer, and `UNVERIFIABLE` is neither: `DOMAIN.md` scopes it to evidence that cannot be obtained from here, and both of these are one `ls` away. The fixture copies under `scripts/lint-fixtures*/` sit outside these globs deliberately; a real self-test landing in any other directory must be added to the loop, which otherwise skips it silently. The loop does not short-circuit, because an `&&` chain hides every gate after the first non-zero. Read each `exit=` against the five-state **Exit-code taxonomy** (`scripts/README.md` is its home, and names all four trees this loop runs, `global/hooks/` and `.claude/skills/*/scripts/` included): 0 is clean; **1 is at least one FAIL** — a finding against the repo; **2 is partial or nothing checked** — a self-test uses it for a run that graded what it could reach and left a branch unexercised, a linter for a tree with nothing to check, `skill-usage.sh` for a count carrying a `+` floor marker; **3 is a usage error** — the gate's own invocation was wrong and nothing was checked, a broken run to fix and re-run, never a finding against the repo; **4 is a check that never ran** — the script itself is broken, which is a claim about the gate and never about the corpus. A partial is reported as a partial, never as the sweep's green.
- The doc-claim check over `README.md`, `src/which-skill/SKILL.md`, `DOMAIN.md`, and `global/README.md` — the documents that claim what the suite is, the always-on rules layer included. Call the Skill tool with `doc-claims` and run it over all four. What each answers to: the router and README blurbs answer to the skill descriptions under `src/`; `DOMAIN.md` answers to the tree for its counts, paths, and names, and to nothing for its rulings; `global/README.md` answers to `global/rules/*.md` and the hook headers for its roster, blurbs, and contracts. A **PASS** needs no line. A **FAIL**, a **STALE**, or a **CONTRADICTS** pair (one finding over two claims, both lines quoted, never settled by the sweep) is a finding, appended to `open-findings.md` in step 3; an **UNSUPPORTED** or an **UNGROUNDED** is listed in the report as a candidate task and never opened as a finding. Every verdict `doc-claims` mints — the five in its table and the **UNGROUNDED** its derived-documents pass adds — lands in one of those three routes. Churn is why a document was read, never a finding (`doc-claims` states the rule): the report names which `src/*/SKILL.md` descriptions changed since the last health report (`git log --since=<that date> --pretty=format: --name-only -G'^description:' -- 'src/*/SKILL.md' | sort -u`; on the first run, with no prior report, every row is re-read and the report says so) as the reason the router and README rows were re-read.
- **Cross-reference check** — every reference file a `SKILL.md` names resolves (lint covers the inline-link form; this step reads the prose pointers too), and no document uses a term `DOMAIN.md` lists under `Aliases to avoid` as if it were the term. The scope is `ls src/*/SKILL.md src/*/references/*.md .claude/skills/*/SKILL.md DOMAIN.md README.md CLAUDE.md global/README.md global/rules/*.md` — the root documents and the always-loaded rules included, because a misused alias lands in the glossary's own prose, the routers, and always-loaded rule prose as readily as in a skill body. **Take the search form from the alias cell, one alias at a time**: the cell names the shape it bans and the grep matches that shape, so `` behavior (bare, as a skill kind — "the `X` behavior") `` is searched as ``grep -rIn 'the `[a-z/-]*` behavior\b'``. A cell that says *bare* bans the unbolded word, and a search matching only `\*\*<alias>\*\*` reports clean on every one of those cells — bolding a domain term is `DOMAIN.md`'s own convention, not the corpus's, and the author being hunted is one who does not know the word is an alias and so does not bold it. The bold grep is a cheap first pass, never the check. Strip a cell's parentheticals and cross-references before matching — `Stack skill (that is a **Convention skill**)` bans `Stack skill` — since a comma split of the raw cell manufactures aliases nobody wrote and lands them on real terms. A stripped cross-reference is still followed before grading a hit: a cell pointing at § Flagged ambiguities carries that bullet's carve-outs, and stripping the pointer without reading what it points at is how the arm flags text the glossary explicitly allows. Before reading a zero as clean, run the positive control the global evidence rule requires (`~/.claude/rules/evidence.md`): the same grep against an alias you know is present. `DOMAIN.md` § Flagged ambiguities is in scope too, and is the half this arm keeps forgetting: its bullets ban shapes no `Aliases to avoid` cell carries — a bare *ledger*, a bare *drift*, a bare *mutation* — so an arm that reads only the table's third column reports clean on every one of them. Take the search form from the bullet the same way, and read its carve-outs before grading a hit: several bullets exempt anaphora, a verb, or one named skill's prose, and a grep that cannot see the exemption manufactures findings against text the glossary allows. **This arm grades `PASS` or `FAIL` and mints no marker of its own** — the doc-claim vocabulary above is that check's alone, and a heading like `### FINDING` is an unregistered marker `DOMAIN.md`'s Status-marker row refuses.
- **Router honesty** — every `src/` directory appears in the router and README with a blurb that still matches its description (lint checks the mention; this checks the blurb). `PASS` or `FAIL`, the same two this arm shares with the cross-reference check.

### 3. Report against the open findings

Write `docs/health/<date>.md`: the `Measured-tree:` line the global evidence rule (`~/.claude/rules/evidence.md`) requires of a report that carries counts, which documents were read and why, then each finding with the check that raised it and the line it quotes.

**The stamp is `git rev-parse HEAD^{tree}`, taken before the report is written** — the in-tree-report spelling `review-changes`' `tree-stamp.md` owns, not a rule of this skill's own. This report is an untracked file written into the tree it names, so the one-liner would fold the half-written report into its own hash; on the clean tree this sweep requires, the two return the same hash and `HEAD^{tree}` is the one still re-derivable after the report lands. The sweep therefore runs on a **clean working tree** and says so beside the stamp; run it dirty and there is no stamp to write.

Every finding takes an ID of the form `H-<nnn>`, assigned once in report order across the whole life of `open-findings.md` and never reused or renumbered — `H` for health, the scheme that lets a later sweep say "H-002 still reproduces" instead of re-describing it. It is this skill's alone and does not collide with `review-changes`' `F<n>` (`DOMAIN.md` **Finding ID**), which is per-report.

Then diff against `open-findings.md` — findings are **additive**: a finding it already lists is carried, never re-raised as new; a new one is appended as open with its next `H-<nnn>`, a `Quoted:` line carrying the text the check flagged, and a `Ground:` line carrying the command that raised it and what it returned. Those are the two fields § Closing a finding reads back, so a row written without them cannot be closed.

## Closing a finding

Closing runs **outside a sweep** — step 1 refuses while anything is open, so no sweep can reach the close. It is a hand edit in the fix session that made the finding stop reproducing, and it is that session's last act:

1. Re-run the check that raised the finding, from the `Ground:` line the row carries. It must now come back clean, with the command and its output in the fix session's report. A close that finds the ground itself was wrong relabels that line `Ground as filed:` and takes step 3, not this one.
2. Move the row from `## Open` to `## Closed` in `docs/health/open-findings.md`, keeping its `H-<nnn>` and its `Quoted:` line.
3. A finding that **never reproduced** — the check was wrong, not the corpus — is moved to `## Closed` and marked `withdrawn`, with what the check got wrong. Withdrawn is not fixed, and recording it as fixed hides a broken check.
4. The commit SHA cannot exist inside the commit that carries it, so the row is closed in **two commits**: the fix commit lands the corpus change and the moved row, and a second commit touching only `open-findings.md` writes that first SHA into the row. Both are outward acts and both are asked for. The second commit moves the tree past the last stamp, so in a `Review required: yes` repo it needs a fresh `Reviewed-tree:` before its push — the sequencing `handoff` spells out, and the reason the close is the fix session's last act rather than an errand for the next one.
