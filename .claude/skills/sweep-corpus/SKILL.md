# Sweep Corpus

The health checks fire only when something schedules them; this skill is the schedule, running the doc-claim check, the lint gate, and the cross-reference check over this repo. It **reports and never edits `src/`** (its only writes are the two files under `docs/health/`): the fix for a finding is a normal session's work, landed through review.

## Refuse while a finding is open

Read `docs/health/open-findings.md` (create it empty on the first run). A finding still listed as open stops the sweep: report the open finding and exit. Refreshing the open list over an unfixed finding is how a sweep becomes a log nobody reads.

## Workflow

### 1. Run the family

- `bash -c 'for g in scripts/lint-skills.sh scripts/lint-adrs.sh scripts/*-selftest.sh scripts/git-hooks/*-selftest.sh global/hooks/*-selftest.sh .claude/skills/*/scripts/*-selftest.sh; do [ -f "$g" ] || { echo "SKIPPED $g"; continue; }; echo "== $g"; bash "$g"; echo "exit=$?"; done'` — the mechanical gate, verbatim output kept. **Run it under `bash`, not the login shell**: under zsh an unmatched glob is a fatal error and the loop never runs, so the gate reports nothing and reads as silence rather than as failure. Every self-test under `scripts/`, `scripts/git-hooks/`, `global/hooks/`, and `.claude/skills/*/scripts/` runs here, derived by the `<script>-selftest.sh` pairing rather than named by hand (the same derivation `scripts/git-hooks/post-merge` makes): a gate nobody runs degrades exactly as silently as no gate. That is why the miss branch prints `SKIPPED` rather than continuing quietly — a renamed linter and an unpopulated glob both have to say so, and today `.claude/skills/*/scripts/` holds no self-test at all, so a `SKIPPED` line for it is the expected output and not a pass. The fixture copies under `scripts/lint-fixtures*/` sit outside these globs deliberately; a real self-test landing in any other directory must be added to the loop, which otherwise skips it silently. The loop does not short-circuit, because an `&&` chain hides every gate after the first non-zero. Read each `exit=` against the five-state taxonomy ADR-0068 fixed: 0 is clean; **1 is at least one FAIL** — a finding against the repo; **2 is partial or nothing checked** — a self-test uses it for a run that graded what it could reach and left a branch unexercised, a linter for a tree with nothing to check, `skill-usage.sh` for a count carrying a `+` floor marker; **3 is a usage error** — the gate's own invocation was wrong and nothing was checked, a broken run to fix and re-run, never a finding against the repo; **4 is a check that never ran** — the script itself is broken, which is a claim about the gate and never about the corpus. A partial is reported as a partial, never as the sweep's green.
- The doc-claim check over `README.md`, `src/which-skill/SKILL.md`, `DOMAIN.md`, and `global/README.md` — the documents that claim what the suite is, the always-on rules layer included. Call the Skill tool with `doc-claims` and run it over all four. What each answers to: the router and README blurbs answer to the skill descriptions under `src/`; `DOMAIN.md` answers to the tree for its counts, paths, and names, and to nothing for its rulings; `global/README.md` answers to `global/rules/*.md` and the hook headers for its roster, blurbs, and contracts. A **PASS** needs no line. A **FAIL** or **STALE** is a finding, appended to `open-findings.md` in step 3; an **UNSUPPORTED** or an **UNGROUNDED** is listed in the report as a candidate task and never opened as a finding. Every verdict the run returns lands in one of those three routes. Churn is why a document was read, never a finding (`doc-claims` states the rule): the report names which `src/*/SKILL.md` descriptions changed since the last health report (`git log --since=<that date> --pretty=format: --name-only -G'^description:' -- 'src/*/SKILL.md' | sort -u`; on the first run, with no prior report, every row is re-read and the report says so) as the reason the router and README rows were re-read.
- **Cross-reference check** — every reference file a `SKILL.md` names resolves (lint covers the inline-link form; this step reads the prose pointers too), and no document uses a term `DOMAIN.md` lists under `Aliases to avoid` as if it were the term. The scope is `ls src/*/SKILL.md src/*/references/*.md .claude/skills/*/SKILL.md DOMAIN.md README.md CLAUDE.md global/README.md global/rules/*.md` — the root documents and the always-loaded rules included, because a misused alias lands in the glossary's own prose, the routers, and always-loaded rule prose as readily as in a skill body. **Take the search form from the alias cell, one alias at a time**: the cell names the shape it bans and the grep matches that shape, so `` behavior (bare, as a skill kind — "the `X` behavior") `` is searched as ``grep -rIn 'the `[a-z/-]*` behavior\b'``. A cell that says *bare* bans the unbolded word, and a search matching only `\*\*<alias>\*\*` reports clean on every one of those cells — bolding a domain term is `DOMAIN.md`'s own convention, not the corpus's, and the author being hunted is one who does not know the word is an alias and so does not bold it. The bold grep is a cheap first pass, never the check. Strip a cell's parentheticals and cross-references before matching — `Stack skill (that is a **Convention skill**)` bans `Stack skill` — since a comma split of the raw cell manufactures aliases nobody wrote and lands them on real terms. Before reading a zero as clean, run the positive control the global evidence rule requires (`~/.claude/rules/evidence.md`): the same grep against an alias you know is present.
- **Router honesty** — every `src/` directory appears in the router and README with a blurb that still matches its description (lint checks the mention; this checks the blurb).

### 2. Report against the open findings

Write `docs/health/<date>.md`: the `Measured-tree:` line the global evidence rule (`~/.claude/rules/evidence.md`) requires of a report that carries counts, which documents were read and why, then each finding with the check that raised it and the line it quotes. Then diff against `open-findings.md` — findings are **additive**: a finding it already lists is carried, never re-raised as new; a new one is appended as open. A finding that stopped reproducing is marked closed with the commit that closed it, never silently dropped.
