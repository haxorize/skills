# `onboard-me` admitted: a read-only KT session over a repo

Status: accepted (2026-08-27)

The 2026-08-27 round surfaced four knowledge-transfer candidates sharing one shape — `describe-product` (N1a.53), `onboard-me` (N1b.22), `offboard-me` (N1b.25), `rebuild-me` (N1b.28) — every one user-invoked, high-stakes, and parked in the ledger for want of a second consumer. The [Team-fit test](0063-team-fit-test-replaces-retire-on-zero-window.md) admits them on the moment rather than the count. This record covers `onboard-me`, a user-invoked skill that runs a knowledge-transfer session over a repo the person does not know: evidence-tagged findings, an honest map of what is still dark, one rung per turn, and each topic worth going deeper on named to the learner to take to `/teach-me`. It reads the repo and never changes it.

The moment is a **recurring** one, and the record is written for the recurrence rather than for a date. One engineer joins on 2026-08-31 and three follow; every one of them opens a repo nobody has walked them through, and the fourth needs the skill exactly as much as the first. A record pinned to a single start date expires the week it lands and takes the skill's justification with it. The role is that engineer. What makes the moment costly is that the alternative is a senior engineer's afternoon, repeated per joiner, producing nothing durable.

`onboard-me` is a new skill rather than a fold into `teach-me`, which the ledger named as the first fold target. A KT session and a lesson are different shapes. `teach-me` runs mission intake, then one lesson per sitting against a per-topic workspace; a KT session's product is a *map* — what is lit, what is still dark, and which unknown is worth lighting next. Folding the map into a lesson sequence would make the repo the mission and lose the map, and a learner who cannot yet name a mission for a codebase is precisely the person a lesson cannot serve. The two compose instead: `onboard-me` builds the map and names each topic for the learner to take to `/teach-me`, whose workspace is the learner's durable record. `teach-me` carries the reverse pointer, so a learner who arrives there without a topic is sent here.

**The map lives in the learner's workspace, keyed on the repo.** It is `kt.md` at the top of `<learning root>/<repo-directory-name>/`, where the root is the one `teach-me` persists as a user memory, defaulting to `~/learning/`. The workspace is keyed on the repo rather than a topic slug, because a KT session has a repo and not yet a topic. No `mission.md` is written: `teach-me` writes one when the learner brings back their first topic, which breaks the cycle in which the workspace needs a mission, the mission comes from the map, and the map goes in the workspace. Nick settled this in the build's review. The KT session writes no `.kt/` trail into the repo as its upstream does, because a second trail beside the learning workspace would split the record in two and leave a directory behind in someone else's repo.

**The product description is not part of this skill.** [ADR-0065](0065-product-description-model-invoked-not-onboard-me-phase-0.md) admits `product-description` as a model-invoked skill in its own right. `onboard-me` neither declares nor calls it, and never offers to write a description; its `requires:` is `writing-for-humans` alone. Before the first rung it reads an existing `docs/product-description/` as evidence, whose claims stay **[inference]** until checked against the code at the current commit, and where there is none it says so and goes on. It does not call the skill because `product-description` is an opt-in skill, installed only into repos that list it, and a global skill may not require an opt-in one ([ADR-0114](0114-opt-in-skills-install-per-repo-from-a-shared-skills-line.md)); on 2026-10-17 Nick chose to drop the call over keeping `product-description` installed everywhere. `rebuild-contract` ([ADR-0069](0069-rebuild-contract-pre-rewrite-contract-in-repo.md)) is the skill that declares it. **There is no `--describe-only` mode**: the door for a BA or PM is the description's own model invocation, which needs no command.

The split between the two is subject, not role: `onboard-me` maps the inside, how the system is built, and `product-description` records the outside, how the product behaves for its user. Both roles need both views at different moments, which is why neither skill is written for a job title.

**The map never carries a secret's value.** The skill writes no code, so its secrets surface is *transcription*: quoting a config value as a **[fact]** into a map that lands outside the repo and outside its `.gitignore`. The **[fact]** tag's definition (`references/evidence-tags.md`) carries one clause for it — cite `file:line` and the kind, never the value. A broader secrets prohibition was drafted and cut: two fresh-context controls under combined time, authority and social pressure, the second with the escape hatch closed, both refused to inline live credentials into code unprompted, and `testing-skills.md` reads a clean control as proof the wording is a no-op. Those controls tested code, not transcription, so they license the cut on the code surface only. The controls were agents in this harness carrying the user's global rules, which is the scope of the finding.

**Nick decided to admit the skill**, as the Team-fit test requires the record to state; the grill put the counter-case on it. Two alternatives lost. Keeping all four candidates parked until an ask arrives — the round's own recommendation — was rejected once the Team-fit test replaced the count: the moment is named and recurring, and a skill that lands the week after the engineers start is a skill that did not exist when it was needed. Folding into `teach-me` lost for the reason above.

## Consequences

- `offboard-engineer` and `rebuild-contract` landed under their own records; `rebuild-contract` declares `requires: product-description` and calls it.
- `onboard-me`'s one repo write is `docs/inward-spec.md`, and only when the learner asks for it. The map, the unknowns, and the per-topic records land in the `teach-me` workspace outside the repo.
- `src/teach-me/SKILL.md` names `/onboard-me` for a learner who cannot yet name a mission for a codebase, and its workspace tree carries `kt.md` as a file it reads and never writes; the router and README carry both directions.

## Deferred

- Whether the map's evidence tags belong in `teach-me`'s own progress format, so a resumed KT session reads them back without `onboard-me` loaded — settled by the first resumed session that needs them.
- Whether an agent works out from the skill body alone that the map lives outside the repo, or only does so when told. Two controls this round were told by their scenario; neither tested the body on its own. Settled by a control that is not told.
