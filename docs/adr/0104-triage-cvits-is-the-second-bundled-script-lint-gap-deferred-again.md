# triage-cvits is the second bundled script; the `src/*/scripts/` lint gap is deferred again

This amends [ADR-0103](0103-bundle-deterministic-skill-logic-as-a-tested-script.md). `triage-cvits` is the second skill to bundle a deterministic script under `src/<skill>/scripts/` — `scripts/classify-cvit-findings.py` with `classify-cvit-findings-selftest.sh` and a `classify-cvit-findings-fixtures/` directory beside it — which is the exact "Revisit when" trigger ADR-0103 named for closing the lint-and-gate-roster gap ("a second skill bundles a script under `src/<skill>/scripts/`, at which point the lint and gate-roster gap above is worth closing"). We hit the trigger and **chose to defer closing it again**: the selftest is run by hand and by `scripts/mutation-sweep.sh --target`, as ADR-0103 describes, and `lint-skills.sh`'s pairing walk still does not reach `src/*/scripts/` or match a `.py` extension. — amended: see Amendments 2026-10-10

We deferred rather than closed because closing it is still the wider blast radius ADR-0103 weighed — teaching the `lint-skills.sh` pairing walk, the `post-merge`/`pre-commit`/`sweep-corpus` rosters, and `scripts/mutation-sweep.sh` a new tree *and* a non-`.sh` extension — against two consumers, both of whose selftests are green and run by hand this round. The opposite choice (close the walk gap now that a second consumer exists) is defensible and is what ADR-0103 anticipated; we judged the roster-and-extension work still larger than the guard it buys for two scripts. The trade-off should tip once a third such bundle lands or one of the two selftests is found rotted, which the `Revisit when` line below records.

The classifier's own design decisions — the three-tier cascade, the two-tree differential, the conservative Bucket-A default for base findings — live in `src/triage-cvits/SKILL.md` and the playbook's `DOMAIN.md`/CVIT-buckets ADR, not here; this record is only about the bundled-script boundary and the open questions the classifier leaves standing.

## Deferred

- **A no-PURL application component is asserted Bucket A, `confirmed=True` rather than flagged** (review finding F6). `is_base_layer` ends `return not purl`, so a finding with an empty PURL and a path matching neither a tool-bundle nor an app-dependency marker classifies as a base runtime and, with a Dockerfile read, asserts A/confirmed. This is correct for a genuine base runtime (the `node` binary — every no-PURL finding in the first real export is one), but a no-PURL *app component* (Prisma blanks the PURL for some findings) would be asserted safe-to-reassign against SKILL.md's "a missing input flags, never asserts." Left as-is because distinguishing a base runtime from a no-PURL app component with no path signal is a real design question, not a one-liner, and no no-PURL app component is confirmed to appear in a real export. Settles when: a real export is shown to carry a no-PURL application component (the measurement), at which point the fallthrough is made to flag (`confirmed:false`) rather than assert. — settled: see Amendments 2026-10-10
- **A release line below the major at a non-zero major is read as one line** (review finding F1). `release_line` in `classify-cvit-findings.py` keys a version on its major, except at major 0 where semver makes the minor the breaking boundary and the key is `(0, minor)`. So a Fix Status naming one fix per *minor* line at a non-zero major — "fixed in 3.11.9, 3.10.1" against an install of 3.11.2, the shape Python, .NET and some Node LTS advisories use — reads as a single 3.x line and compares the install against both entries, letting 3.10.1 clear an install below its own line's 3.11.9. That is the cross-line compare the function exists to prevent (the undici 8.x/7.x case), one segment down, in the unsafe direction: bucket E, `confirmed: true`, so the finding never reaches the upgrade bucket. Left as-is because the fix is not a deeper key but a per-ecosystem one — npm treats 4.19.2 and 4.19.3 as one line while Python treats 3.10 and 3.11 as two, and `release_line` currently has no ecosystem argument — and because no npm export is confirmed to carry a minor-keyed Fix Status (every multi-line case in the first real export splits on the major). The zero-major half of the same question *was* closed, because semver makes 0.x unambiguous without knowing the ecosystem. Note the selftest deliberately carries no fixture separating the two schemes at a non-zero major (CVE-0015's 4.19.2/4.19.3 share a minor, so they are one line under either key); adding one would freeze an answer this record has not picked. Settles when: a real export is shown to carry a Fix Status whose entries share a non-zero major and differ in minor (the measurement), at which point `release_line` takes the finding's ecosystem and keys per-ecosystem. — settled: see Amendments 2026-10-10
- **The `npm ls` → `{name: version}` reduction in SKILL.md step 3 is unspecified** (review finding F8), so the determinism the bundled script exists to provide is lost one layer up: `npm ls --json` emits a nested, recursive tree with duplicate names at different versions and `invalid`/`missing`/`extraneous` flags, and "reduce each to a `{name: version}` map" does not fix how to flatten the recursion, which version wins on a duplicate, or how to treat invalid/missing nodes — so the script's load-bearing input is hand-reduced, model-retyped run to run. Settles when: a bundled reducer script (or a reference spelling out the flatten/dedup/invalid-node rules) is added — the same move ADR-0103 defers for a shared library, scoped here to one skill's input. — settled: see Amendments 2026-10-10

## Revisit when:

A third skill bundles a script under `src/<skill>/scripts/`, or either bundled selftest (`inventory-cvits`'s or `triage-cvits`'s) is found rotted or missing — at which point the walk-and-roster closure ADR-0103 and this record both defer is worth more than the roster work it costs, and the lint walk should be taught `src/*/scripts/` and the script extensions in use. — amended: see Amendments 2026-10-10

## Amendments

- **2026-10-10** — The review of the work-machine import reversed this record's deferral in the same change. `lint-skills.sh` now walks `src/*/scripts/*.sh` and `src/*/scripts/*.py` with the pairing contract of `scripts/`, and `pre-commit` queues a staged bundled script's selftest (and every such selftest when a `scripts/*-lib.sh` is staged): ADR-0075's 2026-09-01 walk showed the closure is a few lines, and the "found rotted" trigger could not fire while nothing ran the selftests. `scripts/mutation-sweep.sh` has no `--target` option and still does not reach these scripts, so their mutation checks stay hand-run. The three deferrals are settled in `classify-cvit-findings.py` rather than on a measurement, per the repo's `Defect policy: fix, don't file`: a no-PURL finding outside an app path is A **unconfirmed**; an at-or-above verdict is asserted only when the major and (major, minor) keys agree, otherwise F unconfirmed; and a nested-path finding is judged by its own row's version, with the `npm ls` reduction spelled in `triage-cvits` step 3. The classifier's bucket definitions now live in `src/triage-cvits/references/buckets.md`, not the playbook.
