# Ship is its own user-invoked skill, not `implement`'s tail

> **Amended by [ADR-0052](0052-committing-extracted-from-ship.md):** the claims discipline, the closing-comment contract, closure verification, the blocked-action protocol, and the one-commit fast path move out of `ship` into the model-invoked `committing`, which `ship` declares; the general verify-before-asserting behavior this record rejected is answered by a discipline with a narrower trigger rather than overridden.
> **Amended by [ADR-0045](0045-ship-commit-style-default-and-closing-contract.md):** its 2026-08-08 amendment promotes the house commit style to the default, replacing the consequence here that per-repo style stays in each consuming repo's `CLAUDE.md`.

The main flow ended at a step nothing owned — `which-skill` listed "6. Ship." while every other step named a skill — and the beat's outbound prose is where unverified claims landed (a closing comment whose review claim was wrong, forcing a correction). **Ship** becomes a user-invoked skill carrying a green, reviewed change to a closed Ticket: commits in **Commit order**, push, then a closing comment — and, where the change needs one, a branch, a PR, and a merge. Every claim in that prose is checked against evidence (scope against the diff, review and coverage claims against `git log <base>..HEAD`) before it is written. Each outward act *yields* the exact command when the environment blocks it rather than retrying around it. **Whether a PR exists at all turns on whether another person must approve the change, not on which host it lives on**: an approver means a branch and a PR, none means it lands on the trunk directly. Keying that fork to the host was rejected because it gets the common case backwards — a solo GitHub repo would manufacture a branch and a PR for the author to approve alone, which is ceremony wearing review's clothes; keying it to the approver makes the no-PR path first-class, and it is the majority path for the work this skill actually sees. Appending the beat to `implement` was rejected because a repo with no tracker never runs `implement` — this repo has neither an `Issue tracker:` block nor issue refs in its commits, yet ships constantly in ordered chunks, so the rule would never fire on a large share of the work it exists for. Extracting a general "verify before asserting" behavior was rejected because its trigger would be every turn, and the failures are gate-shaped: the gates that write durable prose already verify against different evidence each (`capturing-learnings` that cited paths resolve, `handoff` that state matches the live repo, `review-changes` that a HIGH finding quotes `file:line`).

## Consequences

- `implement` *suggests* `ship` the way it already suggests `review-changes` — both user-invoked, so neither can invoke the other.
- Ship owns the **claims** discipline; per-repo commit-message and PR-body *style* stays in each repo's CLAUDE.md. A consuming repo that documents neither (a11y-health today) has its own gap, not this suite's.
- The suite gains a skill whose payload is mostly verification and plumbing. If it stays thin after real use, the fallback is folding it back into per-repo convention — a deletion, not a redesign.
- The related "claimed a step ran that never ran" failure is *not* covered here: `write-skill`'s Load-gate carve-out exempts built-ins because they cannot fail to load, which reasons from availability rather than execution. Repairing that carve-out is its own change — corrected: see Amendments 2026-08-31

## Amendments

- **2026-08-08** — ADR-0045 amends the second consequence: commit-message and PR-body style no longer stays per-repo. `ship` now applies a house style by default, overridden only by a convention the consuming repo *explicitly declares*; the "say so once" gap-naming behavior retires with it. The claims discipline recorded here is unchanged.
- **2026-08-21** — [ADR-0052](0052-committing-extracted-from-ship.md) moves the claims rule, the closing-comment contract, the blocked-action protocol, and a one-commit fast path to the model-invoked `committing`, which `ship` requires; `ship` keeps the split and PR path. "Ship owns the claims discipline" above now reads as `ship` inheriting it through that dependency, and the house style the 2026-08-08 entry gave `ship` is `committing`'s.

- **2026-08-31** — the carve-out above is repaired in `write-skill`'s `cross-skill-wiring.md`, reasoning from execution: a built-in cannot fail to load but can fail to run, and it emits no load line for a gate to watch, so a body that fires one names the artifact the run leaves and treats the step as run only with that artifact in hand. The gate stays refused for built-ins; what replaces it is an evidence check, which is the shape the "claimed a step ran that never ran" failure actually takes.
