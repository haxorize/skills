# A `global/` layer of rules that fire with no skill loaded

Two rules failed in the measured window while existing as text: "no em dashes in outbound prose" (a memory entry) and "commits go through `/ship`" (the ship skill's premise). Both failed the same way. A skill's rule binds only while the skill is loaded, and a memory entry binds only while it is recalled; the failures happened in turns where neither held. The work machine, where most of them happened, cannot pull this repo's memory file at all. The fixes the round adopted for the trust cluster, the evidence rule, the recommend-and-proceed bins, the no-unasked-commits rule, and large-write-chunking, all share this property: they govern chat output and ad-hoc turns, which is exactly where no skill is in force.

## Decision

The repo has a `global/` directory. `global/rules/*.md` holds rules that a user's `~/.claude/rules/` picks up on every turn; `scripts/install.sh` symlinks them there additively, pruning only links that point into this repo's own `global/`, and never touches `~/.claude/CLAUDE.md`. `global/hooks/` holds hook scripts; `install.sh` prints the `settings.json` snippet that wires a hook and never edits `settings.json`, because a settings file merged by a script is a settings file the user no longer knows the contents of.

Five rules ship: `evidence`, `recommend-and-proceed`, `no-unasked-commits`, `large-write-chunking`, and `outbound-dash-sweep`, the em-dash rule that failed as prose in memory, added once the failing case was a Teams draft typed with no skill loaded. The directory is capped at 12,000 bytes by `check_rules_bytes` in `scripts/lint-skills.sh`; the cap is permanent, and a rule that cannot fit is relocated behind a pointer, never refused ([ADR-0079](0079-per-turn-load-ceilings-are-permanent.md)). Three rules already moved most of their mechanics out that way: `evidence`'s empty-check procedure into a `committing` reference, `large-write-chunking`'s file mechanics into `handoff` § Where to write it, and the dash pipeline into `writing-for-humans`' `scripts/dash-sweep.sh`.

The first hook is `rename-safety`, a PreToolUse check on Bash. It blocks an in-place edit, the in-place flag found as an argument of the program that runs (`sed -i`, `perl -pi`, `ruby -i`, and `xargs` or `find -exec` feeding them), however the flag reaches that program; it tokenizes the command line through the scanner the hooks share (`global/hooks/hook-lib.py`, [ADR-0054](0054-commit-bypass-hook-always-on.md)). It is opt-in by directory and judged by target: it acts only on an edit whose files lie in an opted-in directory, read the way the program reads its arguments, and falls back to the directory the command runs in when the file list is not literal (a glob, an unexpandable variable, files fed by `xargs` or `find`). Inside that directory one shape runs: BSD `sed -i ''` (or `-i.bak`) with one substitution and no `g` flag on one listed file, the edit the harness itself suggests, which cannot reach a file nobody listed. Everything else is blocked with a message that points at the Edit tool. It fails open, and carries its own expect/reject selftest, because a fail-open gate whose rule drifts is indistinguishable from a clean run. Six later hooks join it under the same contract, fail-open with a selftest beside each. Three more are `PreToolUse` checks: `commit-bypass`, always on ([ADR-0054](0054-commit-bypass-hook-always-on.md)), `review-receipt`, a precondition on disk rather than a command-line shape ([ADR-0059](0059-review-receipt-hook.md)), and `staged-secrets`, the content a commit would carry. `friction-log` is a `Stop` sensor that reads the finished turn ([ADR-0091](0091-batch-8-admissions-2026-09-12.md)). `context-nudge` (on `UserPromptSubmit`) and `repeat-failure` (on `PostToolUseFailure`) are a third kind: they add one line of context after the fact and never block. A hook is the file whose header carries an `# Install note:` line, which is how `install.sh` tells it from the lib and selftest files beside it. Its header names its dependant in a `Depends:` line, and that skill cites the hook back; `global/README.md` carries the roster.

## Why rules and not hooks

A hook sees tool calls, file writes, and, as a Stop hook, the final message; a PostToolUse hook reads the files a claim lands in. So the surface is mostly visible. What a hook cannot see is the judgment each rule turns on: whether the evidence supports a claim, whether a commit was asked for, which bin a question falls into. The one trial of a shape check found nothing: the 2026-08-27 round's batch 9 ran a claims regex over 75 handoff and review files in the landing zone and 112 commit messages in this repo's log, and it matched prose about verification and never a claim the rule had missed. Where a hook *can* see the failure, as with an in-place edit, a bypassed commit hook, or an unreviewed push, the hook is the right rung. This section is the ground [ADR-0051](0051-usage-evidence-mining-round.md) cites for still rejecting an em-dash `Stop` hook: judgment, and one measured trial of a regex that caught nothing the rule had missed, not reach.

## Admission rule

`global/` holds only rules a skill depends on. Each rule has an entry in the `global/rules/DEPENDS` sidecar naming the depending skills (the sidecar, not the rule file, because a rule's bytes load on every turn), and lint checks that each name resolves and that the named skill cites the rule, in one of two forms: the path `~/.claude/rules/<stem>.md` or the backticked stem. A sentence stays in a rule only if a session needs it before it knows to look, the test [ADR-0076](0076-claude-md-admits-triggers-and-contracts-only.md) gave `CLAUDE.md`; the rest moves into the skills whose acts it describes.

Each rule's `Why not a hook or lint:` control is recorded here, not in the rule file, because it is admission evidence for a maintainer, not a rule the loaded session obeys; the five lines cost 2,214 bytes on every turn while they sat in the rule files. The control is the count `global/README.md`'s key defines: over a stated window of at least 30 days of the artifacts the rule governs, how many a mechanism would have fired on and how many of those were the failure. A correction to a count lands here. The five, verbatim from the lines as cut, each with its caveat in italics:

- `evidence.md` — a Stop hook can read the final message and a write hook the files a claim lands in — a commit message, a review report, a handoff — but whether the evidence supports the claim is a judgment, not a shape a check can match; a claims regex run on 2026-08-29 over 75 handoff and review files in the landing zone and 112 commit messages in this repo's log matched prose about verification, never a claim the rule had missed. *Non-conforming to the key's contract*: it states a single run date, not a ≥30-day window, and no fire count; re-deriving the judgment-graded match set is not a command a batch can re-run.
- `large-write-chunking.md` — a hook sees the write after it has already been truncated, and cannot see the chat message that was cut mid-section — over the 30 days to 2026-08-30, the transcripts under `~/.claude/projects/` hold 430 `Write` calls and no truncated one (429 end in a newline; the other is an 11-character placeholder), so a size threshold has no failure to key on and refuses whole documents. *The zero-failure count is also why the file-write half moved into `handoff`.*
- `no-unasked-commits.md` — a hook sees the `git commit` call, and cannot tell an asked commit from an unasked one — over the 30 days to 2026-08-30, the transcripts under `~/.claude/projects/` hold 117 real `git commit` calls, 34 with no ask in a user turn, a `/ship`, or an `AskUserQuestion` answer, and one of the 34 the failure (2026-08-22: "Hold up. Did we ship these changes without reviewing them first?"), so a transcript-grepping hook fires 34 times to catch one and reads a handoff-carried ask as the failure.
- `outbound-dash-sweep.md` — the draft is chat output, or a file with no distinguishing name — a Write hook would have to fire on every file, code included, to catch it — and a Teams paste never passes through a tool; over the 30 days to 2026-08-30, the transcripts under `~/.claude/projects/` hold 3,327 assistant text blocks carrying an em dash against 4 draft-shaped ones, so a Stop hook keyed on the glyph fires 3,327 times for 4 drafts. *4 is the draft population, not a failure count: the line never stated how many of the 4 carried a dash.*
- `recommend-and-proceed.md` — which bin a question falls into is a judgment the harness cannot see — over the 30 days to 2026-08-30, the transcripts under `~/.claude/projects/` hold 84 `AskUserQuestion` calls carrying 140 questions and 83 assistant turns closing on a question mark, none of the 140 a fact a command answers, so a hook keyed on the ask has 167 events to adjudicate and no failure among them. *The zero is asserted over the 140 questions while the fire count is 167 events (84 calls + 83 turns); the two populations differ.*

Without this gate the directory becomes a second CLAUDE.md, the place every preference lands because it is global, and the context cost of a rule loaded on every turn is paid by every project the user opens.

## Considered Options

- **Add the rules to `~/.claude/CLAUDE.md` by hand.** Rejected: it is not version-controlled, does not reach the work machine, and the memory-file failure is the evidence that a personal file does not bind.
- **Have `install.sh` edit `settings.json` and `CLAUDE.md`.** Rejected: an installer that rewrites the user's harness config is the trust failure the round is fixing, moved one level up. Printing the snippet keeps the edit a human act.
- **A hook per rule, as the reports suggested.** Rejected per § Why rules and not hooks; a hook ships only where it can see its failure.
- **Rules inside the skills that consume them.** Rejected: that is the arrangement that failed. The consumers are the skills named in each rule's `DEPENDS` entry; the rule lives above them so it holds when they do not load.
- **`rename-safety` opt-in keyed on the directory the command runs in**, as first built. Replaced on 2026-10-12: over 16 days it denied 46 main-session commands, one per session, and 42 of them were not renames: 24 targeted a file outside any repo (a handoff marker under `$TMPDIR`, blocked only because the command ran from an opted-in repo), 12 were mutation probes, and 6 were one-site literal edits in the repo; the 4 rename-shaped commands are still blocked (`~/code/lib/_rounds/2026-10-12/themes/workflow-friction.md` TE-1). An exemption for the handoff folder by name would have covered 14 of the 42.

## Consequences

`install.sh` runs three jobs (skills, rules, hook snippet) and the opt-in post-merge hook from [ADR-0049](0049-opt-in-post-merge-hook-auto-runs-install.md) re-runs all three on pull; the rules share the trust trade-off that record accepted. Lint checks each `DEPENDS` entry and its citations, the rules byte cap, and the 200-line and no-ADR-number checks over `global/rules/`. A rule that loses its last depending skill leaves the directory. `rename-safety` reads a `$VAR` in a file argument from the hook's own environment, so a variable the harness does not export reads as not literal and the directory the command runs in is judged instead.
