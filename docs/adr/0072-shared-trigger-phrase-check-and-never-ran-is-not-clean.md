# A shared trigger phrase is a lint FAIL, and a check that never ran is never a clean one

`write-skill`'s *Writing the description* has always told an author to grep a candidate trigger phrase across the other descriptions before adding it, because a phrase a sibling already carries splits the load between the two and neither fires reliably. The instruction was a grep nobody ran. It is now a check: `scripts/lint-skills.sh` FAILs a **double-quoted** span carried by two or more model-invoked descriptions, reported once per phrase, naming every description that carries it, compared case-insensitively and across straight and curly quotes. `write-skill:99` is rewritten to say a check exists and to keep the grep for the half no check sees.

**The scope is deliberately narrow, and the narrowness is the design.** Only double-quoted spans are compared. An unquoted trigger clause ("when a build turns up a failure") is not read, so two descriptions phrasing one trigger in plain words still pass — that half stays the author's grep. A user-invoked description is never read, since the model never sees it. And the **disambiguating tail is exempt**: the sentence opening `Not for…` or `Don't…` that this repo's own style prescribes quotes the *sibling's* phrase precisely to route a reader away from it, and flagging that would tell an author to delete the routing. `src/adoption-verdict/SKILL.md:3` carries a live instance. Each of those three exemptions has a fixture that must stay quiet, and `scripts/lint-skills-selftest.sh` asserts the fixture property itself is still present, so weakening one fails loudly rather than retiring an assertion.

**The gate.** Surprising without context: a normative check that will FAIL a description a careful author wrote, keyed on a syntactic proxy (quoting) for a semantic rule (overlapping triggers). A real trade-off: catch the mechanical half and accept that quoting is a proxy, against leave the whole rule to the grep — a rational team picks either.

**A check that never ran is never reported as a clean one.** The second half of this decision is a rule for the lint family, adopted here because both linters were restructured in the same change and one of them had the defect. `scripts/lint-adrs.sh` read its rows through `done < <(read_rows …)`, where the producer's exit status is unobservable: an unreadable file, a dying `grep`, a misspelled kind, and a dispatch naming a function that does not exist all yielded "no rows", which the run reported as `OK: 71 records … drew no FAIL`, exit 0. Each of those four now exits **4** — a fifth code, distinct from a FAIL, meaning *this run is not a verdict on anything*. `lint-skills.sh` learns the same lesson structurally: the user-invoked set and both routers are read in a pass 0 before any check runs, so no check's answer depends on how far the pass that asks it has got, and `check_name_field` no longer sits behind the description gate, where one broken description hid a second defect in the same file.

## Considered Options

- **Leave the trigger-phrase rule to the author's grep.** Rejected: `write-skill` has prescribed that grep since the file existed, and the corpus still carries backticked phrases shared across sibling descriptions. A rule that is written, cited, and unenforced drifts the same way `adr-format.md`'s pointer did.
- **Compare unquoted trigger clauses too.** Rejected: there is no reliable span boundary in prose, and the false-positive class is descriptions that legitimately share ordinary English. The check would be silenced by rephrasing away from clarity.
- **A `sibling_groups`-style registry so a phrase two skills legitimately share can be exempted.** Rejected as unbuilt-until-needed: with the disambiguating tail exempt, no legitimate sharer is known. The cheapest wrong remedy — deleting the quotes — breaks the proxy, so if that starts happening the registry is the fix, and this is the record to amend.
- **Make an unknown row kind in `lint-adrs.sh` a FAIL rather than a new exit code.** Rejected: a FAIL says the corpus is wrong, and the corpus is not wrong — the script is. Exit 4 says the run has no verdict, which is what a caller reading the status alone needs to know.

## Consequences

- The lint family's exit-code taxonomy gains **4 — a check never ran, so this run is not a verdict** ([ADR-0068](0068-adr-linter-and-two-way-pointer-enforced.md) set 0–3; `DOMAIN.md` carries the row). It is reserved for the script being broken, never for the corpus being wrong.
- `lint-skills.sh --help` prints the check roster, read out of the script's own header between two markers, so `--help` and the header cannot drift; `CLAUDE.md`'s § Linting sentence is condensed to point at it rather than paraphrase it, having been wrong immediately after being maintained.
- `lint-adrs.sh` checks its own kind→check pairing both ways: a dispatch naming a kind `read_rows` does not define, and a kind `read_rows` defines that nothing dispatches, each exit 4.
- Both linters' headers now defer to `lint-skills-selftest.sh`'s NOT-covered list rather than claiming it grades every check. Eight checks can be disabled with that selftest still green; the selftest header is the authority and says so.
- The nine control-clean rules that [ADR-0069](0069-rebuild-contract-pre-rewrite-contract-in-repo.md), [ADR-0070](0070-offboard-me-handover-in-repo-human-as-evidence.md) and [ADR-0071](0071-evaluation-ledger-multi-week-evaluation-in-repo.md) retained are held on a ground each of those records now states for itself: a control that held on this harness, under the user's global rules, is evidence about the harness, not about the rule. Whether that reading has become the default — and therefore whether `testing-skills.md`'s flat "if the control doesn't exhibit the failure, stop" still describes practice — is open below.

## Deferred

- Whether `src/write-skill/references/testing-skills.md:7`'s flat rule still describes practice, given that three records in one batch retained control-clean rules on the harness-scope ground above. Either the rule is narrowed to say so, or the nine rules are cut. Settled by an amendment here recording which, written after the next skill's micro-test either does or does not reach for the same ground.
- Whether the quoting proxy holds. Settled by the first FAIL an author answers by deleting the quotes rather than rephrasing — at which point the exemption registry rejected above is built and this record amended.

Revisit when: a correct description is FAILed by this check and the fix is to delete quotes rather than to rephrase, which would mean the proxy has stopped standing for the rule; or when two model-invoked descriptions share a plain-prose trigger and neither fires reliably, which would mean the narrow scope is the wrong half.
