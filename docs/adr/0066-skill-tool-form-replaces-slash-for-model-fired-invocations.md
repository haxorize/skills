# The Skill-tool form replaces the slash for every model-fired invocation

Status: accepted (2026-08-28)

This amends [ADR-0019](0019-prose-invocation-tiers-load-bearing-vs-opportunistic.md).

That record ruled that the slash marks a reference as *invoked*: "slash every real invocation — load-bearing delegations, a model-invoked skill's own ungated delegation (`tdd` → `/feedback-loops`), and human suggestions (`/grill-me`)." That premise no longer holds. A bare `/name` aimed at the model asks it to type a command it cannot type; naming the Skill tool is what the model can act on. We therefore **invert the model-facing half of 0019's rule**: `` Call the Skill tool with `<name>` `` wherever the model fires the skill, `/<name>` only where a human types the command, plain backticks where nothing fires. The human-suggestion half of 0019 stands unchanged — `/grill-me` is still slashed, because a human really does type it. Roughly 84 slash tokens across 48 files were converted, and `scripts/lint-skills.sh` now enforces both directions.

**The gate.** *Surprising without context* — clears outright: the tree does the opposite of what its own decision record instructs, in the one repo whose codebase *is* the prose. *Real trade-off* — clears, and 0019 proves it: that record rejected "blanket `/skill` slashing (Matt Pocock's uniform style)", so the rejected alternative is a position a rational team held here until this batch; the alternative weighed and rejected now is keeping 0019's slash-marks-invoked convention and accepting that the marker addresses a typist who isn't there. *Hard to reverse* — the weakest of the three, but real: 84 sites, a rewritten matcher, a new lint check, two fixtures and their expectations.

**A third tier gets its name.** 0019's 2026-08-08 amendment admitted the **lazy load** beside load-bearing and opportunistic, but left a fourth shape unnamed: a model-invoked skill's **ungated soft delegation** — an unconditional imperative that is the step's whole job, carrying no gate because no human watches (`resolving-merge-conflicts` → `feedback-loops`, `adoption-verdict` and `diagnosing-bugs` → `capturing-learnings`). 0019:20 blessed these while the slash was a weak marker; under the new convention they take the strongest imperative the convention has, so the tier is named here rather than left to read as a load-bearing delegation sitting where the invariant forbids one. The invariant itself is unchanged: a load-bearing delegation, with its gate, still lives only in a user-invoked orchestrator.

**Which form a new ADR uses.** Records already written keep their text — `adr-format.md` says amendments never rewrite the original, so the 15 old-form sites under `docs/adr/` stay as they are and `lint-skills.sh` does not walk the directory. A **new** record names a skill in plain backticks: an ADR is read by a person and fires nothing. Only a command that person would actually type is slashed.

**What earns a `requires:` declaration.** A reference that will *fire* the skill earns it — a Skill-tool call, a lazy load, or a gated offer awaiting consent, which is why five peers all declare `adr` for an offer they never fire unprompted. A pure statement of the register the prose answers to, which never fires anything, does not; that is the rule behind `ship` dropping `writing-for-humans` while keeping `committing`, which carries it transitively.

## Consequences

- 0019:21's "**Not yet mechanized** — today it is an authoring discipline carried by `write-skill`" is now false about the tree. `lint-skills.sh` fails a `/name` on a model-invoked skill across every markdown file the repo ships as instructions, and fails a Skill-tool call on a user-invoked skill, whose description the model cannot see.
- The tier test in `write-skill` is now a question about the work — *does the next instruction need the target's text in context?* — not about how the sentence is already worded. The previous test was circular and had sorted two structurally identical sites opposite.
- `DOMAIN.md` gains a **Skill tool** row (distinct from **Skill**, which is the directory) and an **Invocation form** row; the latter replaces the coinage "reference form", a fourth "Reference X" in a glossary that already warns about that collision.
- The rule is applied, not deferred: every one of the 22 skills declaring `writing-for-humans` now calls it, and `ship` — which mentions it plainly and fires nothing — is the only skill that names it without declaring it. The declaration set and the call set are the same set, which is the invariant the rule was for.

## Revisit when:

Claude Code gains a hard cross-skill invocation primitive, or the Skill tool's name or calling shape changes — the whole convention is a cache of how the model reaches another skill today.

## Amendments

- **2026-08-28** — The **load-gate condition was circular and is replaced.** *"The invariant itself is unchanged: a load-bearing delegation, with its gate, still lives only in a user-invoked orchestrator"*, in **A third tier gets its name** above, is reversed by this: placement leaves the definition, and the fourth tier's reason for existing is restated below. `write-skill` gated "only on a load-bearing delegation, in a user-invoked orchestrator", and `DOMAIN.md` defined a load-bearing delegation as one that "lives only in User-invoked Orchestrators". The definition contained the placement and the placement was the test, so nothing in either sentence asked a question about the work — what actually predicted a gate was *user-invoked caller plus unconditional phrasing*. This is the same circularity the batch-2 review removed from the tier test, surviving one level down.

  The condition is now two independent tests, both required. **Placement** is unchanged and was never circular: a gate lives only in a user-invoked skill, because it works by a human seeing the `Launching skill:` line, and inside a model-invoked skill there is no watcher — a miss must degrade gracefully. **Necessity** replaces "load-bearing": gate only where a silent miss would make the caller emit the *wrong kind* of artifact rather than a worse one. The procedure is to name what the caller would produce with the target absent and gate only if that thing is the wrong kind — asked of the work, never read off the sentence, since an unconditional imperative is how a gate is written and never evidence that one is warranted.

  **The tiers are re-cut to match.** Removing placement from the definition of a load-bearing delegation left the taxonomy unable to say what a wrong-kind delegation in a model-invoked caller *is* — the shape **A third tier gets its name** above described but did not file. It is now the fourth tier under its own name, **Ungated soft delegation**: the strongest imperative the convention has, never a gate, because no human is watching and a gate nobody reads fails silently. And **Lazy load** widens past its model-invoked-only scoping from 0019's amendment: `to-story` → `writing-for-humans` is a user-invoked caller's ungated imperative whose miss only flattens the prose, which is the lazy-load consequence exactly, and the inline-write scoping 0019 wrote into the row was one form the imperative takes rather than the test. So the two questions run in order — necessity first, asked of the work; placement second, deciding only which of the two wrong-kind tiers the delegation is and whether it gates. Necessity itself gets a decision rule, because it was under-determinate on real sites: read the artifact off *the caller's own body's* description of what it emits, and if that body still prescribes every part of it with the target gone, the miss is worse and not wrong-kind.

  Two corollaries the corpus forced. A **conditional** delegation gates when its condition fires (`implement` → `diagnosing-bugs` runs only on an unexplained red). A **repeat** delegation gates at the site where a miss does the damage, not only at the first mention — `upgrade-deps` had its gate on the baseline check and ran the per-step green check ungated, though "each step ends green" is its whole contract.

  Re-judged at write time, over every shipped file under `src/`: **64 caller/target pairs, of which 32 were gated before this amendment and 30 after**; 59 of the 64 are distinct, the rest being a caller naming one target on two lines. The pairs come from the linter's own clause matcher (`scripts/lint-skills.sh:457`), reused verbatim after a hand count misread the two-target form and undercounted — the same defect the batch-2 review found in the matcher itself. The 32 and the 30 are a second measurement the matcher cannot make, since it never reads a gate: they are per-name, counted line by line, a pair scoring gated when its line carries `Launching skill: <target>` or a bare `Launching skill:` self-check covering the whole clause. That second form is what the hand count missed, and reading it is what makes the figures reproduce. Two consequences worth stating rather than leaving to be rediscovered: a gate discharged by cross-reference instead of gate text (`chart-course:80`) scores ungated under this method, and excluding `write-skill`'s own description of the gate moves nothing, because that line carries no call clause and so produces no pair at all. Six sites change, and no pair disappears: nothing here removes a Skill-tool call. The four `to-*` publishers de-gate `writing-for-humans` and keep their `work-item-shape` gate: strip the register skill and the item still publishes with the right shape in flatter prose, which is worse, not wrong-kind. `address-findings` → `feedback-loops` and `upgrade-deps`' per-step `feedback-loops` gain gates. `upgrade-deps` gates because "each step ends green" is its whole contract. `address-findings` gates on a narrower ground, which the pass's artifact makes wrong-kind rather than worse: its close re-stamps the tree, and the `review-receipt` hook reads that stamp as push authorisation, so a stamp written over a tree whose lint, format, and docs were never swept certifies a state the pass did not check. The disposition table would still be emitted with `feedback-loops` absent; the stamp beside it would be a different thing from the one the hook is built to trust. `explain` and `merge-quiz` keep theirs, not because their output is prose but because they are thin shells with no other method — `writing-for-humans` *is* their procedure, the same shape as `grill-me` → `grilling`.
