# Bundle a skill's deterministic logic as a tested script in its bundle

A skill whose body mixes prose judgment with a chunk of deterministic data-shaping — parsing a file, grouping rows, deriving fields by a fixed rule — ships that deterministic part as a script under the skill's own `scripts/` directory, with a selftest and a fixture beside it, rather than re-deriving it as throwaway code each run. `inventory-cvits` is the first skill in this repository to do so: its CSV-to-Story-body transform (dual-form manifest reader, day-truncated grouping, risk-level ordering, priority-on-missed decision) lives in `src/inventory-cvits/scripts/`, and the body calls it by path.

We rejected leaving the logic as prose the model re-implements per run, which is how the skill worked before. Re-derived code is unversioned and untested: two runs of the same export could group or order findings differently, and the transform's traps — the second-precision target date that must be day-truncated before grouping, the manifest's two accepted forms — have no regression guard, so a later edit reintroduces a bug no test catches. A bundled script with a fixture freezes the transform as a contract: the selftest asserts the drafted body and the three-bin partition against a known input, and the skill stops tracking the model's run-to-run variation. This matches the discipline `write-skill` already names — a deterministic step is a black box the body should not re-explain — and follows the shape of the repo's existing `scripts/*-selftest.sh` convention, used until now only for repo infrastructure (lint, install): the selftest sources `scripts/selftest-lib.sh`, drives a fixture, and reports the three-state exit. It follows that convention by hand rather than under its gate — see the known limitation below.

The portable unit stays "skill + declared deps" from [ADR-0007](0007-self-contained-skill-bundles.md) as [ADR-0016](0016-behavior-skills-declared-deps-relaxed-atomicity.md) amended it: a bundled script travels inside the skill directory, so a skill that installs by symlink carries its script and selftest with it, no new install step and no shared library to resolve.

The script stays **thin and side-effect-free** — data in, data out, no `az` call and no network. The tracker reads (enumerating the Security Feature's children) and the tracker writes (every Story create or update, routed through `/to-story`) stay in the skill body as prose, because they are the audited write path the stormworks-playbook repo's ADR-0018 fixes and a script must not become a side channel around it. What the script owns is the pure transform between the export and the drafted body; what the body owns is deciding which Story each image maps to and handing the draft to `/to-story`. — amended: see Amendments 2026-10-10

## Considered Options

- **Re-derive the logic as prose each run (prior state)** — no new files; rejected because the transform is unversioned, untested, and free to vary run to run, with its two known traps unguarded.
- **Extract the logic to a shared repo-level `scripts/` library** — one home for all skill logic; rejected because it breaks the symlink-live bundle — a skill would no longer install self-contained — for a transform only one skill uses.
- **Bundle a tested script in the skill's own `scripts/` (chosen)** — the transform is versioned, fixture-tested, and travels with the skill; sets the precedent a second such skill follows.

## Known limitation — the selftest pairing is not lint-enforced for a `src/` skill bundle

`lint-skills.sh` enforces the script↔selftest pairing over three trees — `scripts/*`, `scripts/git-hooks/*`, and `.claude/skills/*/scripts/*.sh` — and all three globs match `*.sh`. A bundled skill script lives under `src/<skill>/scripts/`, which no walk visits, and this first one is a `.py` file, which the `*.sh` glob would miss even if a walk reached it. So the discipline this record sets — a bundled deterministic script ships with a selftest and a fixture — holds as authored convention but is **not** caught by lint: a future bundled script added with no selftest, or one whose selftest rots, passes the linter silently. The `src/` location is also outside the `post-merge` and `pre-commit` gate rosters (keyed to the same `*.sh` trees), so nothing runs the selftest automatically; it is run by hand, and only by hand. `scripts/mutation-sweep.sh` does not reach it either: the sweep has no `--target` option, and its roster walks `scripts/`, `scripts/git-hooks/` and `global/hooks/`, so it refuses a `src/*/scripts/` path as a target it does not derive. — amended: see Amendments 2026-10-10

This gap was accepted rather than closed in the same change, because closing it means teaching the lint walk, the `post-merge`/`sweep-corpus` rosters, and `mutation-sweep` a new tree and a non-`.sh` extension — a blast radius wider than the one skill it would guard today. It is recorded here as the revisit trigger below rather than left implicit.

A second, smaller accepted difference: the Story HTML these drafts become through `/to-story`'s pandoc differs cosmetically from the hand-patched oracle Stories — the oracle carries unquoted `id=problem` attributes and a trailing space before some close tags (`Problem </h2>`), artifacts of the pandoc version that produced them. The drafted markdown is the contract; its pandoc output is HTML-equivalent and renders identically in Azure DevOps, so the skill does not post-process the HTML to reproduce those bytes. The one byte that *is* reproduced, because it is visible content rather than markup cosmetics, is the non-breaking space after "vs." in the Out-of-scope paragraph — carried as a literal U+00A0 in the script and pinned by the selftest.

## Revisit when:

A second skill needs the same transform, at which point a shared library under the repo's `scripts/` earns the move this record rejected for a single consumer; or a second skill bundles a script under `src/<skill>/scripts/`, at which point the lint and gate-roster gap above is worth closing (extend the walk to `src/*/scripts/` and teach it the script's extension) rather than leaving each bundle's selftest hand-run; or the stormworks-playbook repo's ADR-0018 single-write-path invariant changes, at which point the thin-script boundary is reopened. — amended: see Amendments 2026-10-10
