# Bundle a skill's deterministic logic as a tested script in its bundle

A skill whose body mixes prose judgment with a chunk of deterministic work — parsing a file, grouping rows, deriving fields by a fixed rule, or running one fixed sequence of calls — ships that deterministic part as a script under the skill's own `scripts/` directory, with a selftest beside it that drives a fixture or a fake of the tool it calls, rather than re-deriving it as throwaway code each run. `inventory-cvits` was the first skill in this repository to do so: its CSV-to-Story-body transform (dual-form manifest reader, day-truncated grouping, risk-level ordering, priority-on-missed decision) lives in `src/inventory-cvits/scripts/`, and the body calls it by path. `triage-cvits` was the second ([ADR-0104](0104-triage-cvits-is-the-second-bundled-script-lint-gap-deferred-again.md)), and `glapi-test-pass` is the first whose script writes to a tracker. `upgrade-deps` bundles `release-age.py` for the release-age floor and publisher lookups. `work-item-shape` bundles `tracker.py`, which every skill that resolves or touches a tracker runs.

We rejected leaving the logic as prose the model re-implements per run, which is how the skill worked before. Re-derived code is unversioned and untested: two runs of the same export could group or order findings differently, and the transform's traps — the second-precision target date that must be day-truncated before grouping, the manifest's two accepted forms — have no regression guard, so a later edit reintroduces a bug no test catches. A bundled script with a fixture freezes the transform as a contract: the selftest asserts the drafted body and the three-bin partition against a known input, and the skill stops tracking the model's run-to-run variation. This matches the discipline `write-skill` already names — a deterministic step is a black box the body should not re-explain — and follows the shape of the repo's existing `scripts/*-selftest.sh` convention, used until now only for repo infrastructure (lint, install): the selftest sources `scripts/selftest-lib.sh`, drives a fixture, and reports the three-state exit. `lint-skills.sh` fails a bundled `.sh` or `.py` script with no selftest beside it, and `pre-commit` runs the paired selftest when the script or its fixtures are staged (`scripts/README.md` § Run the selftest of what you touched). `scripts/mutation-sweep.sh` does not reach these scripts: its `roster()` walks `scripts/`, `scripts/git-hooks/` and `global/hooks/` only, and it rejects a `src/*/scripts/` file given to `--path` as "not a target the roster derives", so no bundled script is mutation-graded.

A bundled script travels inside its owner's directory, so the owner's symlink carries the script and its selftest, with no new install step. A second skill that needs the same script runs the owner's copy by its installed path, `~/.claude/skills/<owner>/scripts/<file>`, and never copies it ([ADR-0108](0108-shared-references-have-one-owner-and-one-copy.md)): `triage-cvits` runs `inventory-cvits`' `find-image-story.py`, and nine skills run `work-item-shape`'s `tracker.py`.

A bundled script makes no tracker write that a user-invoked publisher owns, unless the skills that publish work items run it as their write path. `/to-story`, `/to-tasks`, `/to-feature` and `/to-bug` are the write path for work items, and all four are user-invoked, so a human types each one ([ADR-0106](0106-admit-the-cvit-skills-as-org-bound.md) records it for the CVIT skills); a script that created a Story or edited its fields would be a side channel around them. So the two CVIT scripts stay **thin and side-effect-free**: data in, data out, no `az` call and no network, and the body prints each publisher command for a human to type. What the script owns there is the pure transform between the export and the drafted body; what the body owns is deciding which Story each finding maps to.

A script that the publishers and `chart-course`, the skills that publish work items, run as their write path may make their writes, because it is that path rather than a side channel around it. `chart-course` is not a publisher, but it creates and links work items the same way, so the exception covers it by name. Nick decided this on 2026-10-18.

`work-item-shape`'s `tracker.py` makes each create, body update, parent link and blocking link that the four publishers and `chart-course` made by hand before it. It also posts two comments that were already posted by hand: `review-architecture`'s comment on a story and `chart-course`'s resolution comment on a decision ticket. The reader-side skills (`implement`, `ship`, `backfill-adrs`) run only its `resolve`.

Each create waits on the confirming turn that `publishing.md` § Publish gate requires of the skill that carries it. The Publish gate covers creates only, so each comment goes out at the step of the calling body that posts it, as it did before the script. `work-item-shape`'s own body never runs a write through the script: that skill routes a creation ask to a publisher.

The script does not make every tracker write. State transitions, assignment, close, label edits and a tag apply after a create stay direct `gh` and `az` calls in the calling bodies. Nick deferred widening the script to them on 2026-10-18.

`work-item-shape` owns the script because the 2026-10-12 owner settlement gave it the tracker references. The script replaced three of them (`work-item-tags.md`, `github-sub-issues.md`, `ado-html-transport.md`). The other two, `tracker-resolution.md` and `publishing.md`, remain as procedures that call the script, in 9 and 5 sibling copies until [ADR-0108](0108-shared-references-have-one-owner-and-one-copy.md)'s collapse leaves one each. The script owns what has one right answer: parsing the CLAUDE.md tracker block, the title prefix, the ADO tag set, the GitHub label precheck, Markdown to HTML, the one `--fields` list, the rich-text read-back, and the sub-issue and relation calls. Before it, those rules lived in 29 byte-identical reference copies (60,956 B), and each run re-applied them by hand.

A user-invoked skill whose whole job is one fixed sequence of tracker writes that no publisher owns may run those writes from its script. `glapi-test-pass` is that case. It creates a Test Case, adds a "Tested By" relation from the User Story to it, creates a requirement suite, a test run and a Passed result, and closes the Test Case, so that the GLAPI production deployment gate finds a passing test point on the Story. No publisher owns any of those writes. The relation add is the script's one write on the Story, and it edits no field there; `/to-story` adds only Parent and dependency relations, never a Tested By link. Before the script, the model ran the same `az` calls itself, copied from about 7 KB of shell in the body, and each call needed IDs the previous one returned. The script now makes the calls, and its selftest pins each one against a fake `az` on `PATH` rather than a fixture. The typed command is the ask for the writes, as it was when the model ran them, and the result's comment says that no test was run and names the PR or pipeline run that was checked. Nick decided this in the 2026-10-12 round: grill Q29 cleared the record as compliant (the GLAPI team owns the gate, and his team makes the call), and the 2026-10-16 follow-up narrowed this record's boundary to the publishers.

## Considered Options

- **Re-derive the logic as prose each run (prior state)** — no new files; rejected because the transform is unversioned, untested, and free to vary run to run, with its two known traps unguarded.
- **Extract the logic to a shared repo-level `scripts/` library** — one home for all skill logic; rejected because nothing installs the repo's `scripts/` into `~/.claude/skills/`, while an owner's `scripts/` installs with the owner and every other skill reaches it by installed path.
- **Bundle a tested script in the skill's own `scripts/` (chosen)** — the transform is versioned, fixture-tested, and travels with the skill; sets the precedent a second such skill follows.
- **Keep every tracker write out of a bundled script, `glapi-test-pass` included** — rejected: the rule protects the publishers, and the gate record's writes bypass none of them, while keeping them as prose leaves a sequence of up to 13 calls untested and replayed by hand.

## Accepted difference — the Story HTML is not byte-identical to the oracle

The Story HTML these drafts become through `/to-story`'s pandoc differs cosmetically from the hand-patched oracle Stories — the oracle carries unquoted `id=problem` attributes and a trailing space before some close tags (`Problem </h2>`), artifacts of the pandoc version that produced them. The drafted markdown is the contract; its pandoc output is HTML-equivalent and renders identically in Azure DevOps, so the skill does not post-process the HTML to reproduce those bytes. The one byte that *is* reproduced, because it is visible content rather than markup cosmetics, is the non-breaking space after "vs." in the Out-of-scope paragraph — carried as a literal U+00A0 in the script and pinned by the selftest.

## Revisit when:

A script's consumers outgrow any one owner's job, so that no skill's job defines its content and the owner choice [ADR-0108](0108-shared-references-have-one-owner-and-one-copy.md) asks for has no answer; or a publisher comes to own a write a bundled script outside it makes, at which point that write moves to the publisher.
