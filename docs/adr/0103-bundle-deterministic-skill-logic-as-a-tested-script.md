# Bundle a skill's deterministic logic as a tested script in its bundle

A skill whose body mixes prose judgment with a chunk of deterministic work — parsing a file, grouping rows, deriving fields by a fixed rule, or running one fixed sequence of calls — ships that deterministic part as a script under the skill's own `scripts/` directory, with a selftest and a fixture beside it, rather than re-deriving it as throwaway code each run. `inventory-cvits` was the first skill in this repository to do so: its CSV-to-Story-body transform (dual-form manifest reader, day-truncated grouping, risk-level ordering, priority-on-missed decision) lives in `src/inventory-cvits/scripts/`, and the body calls it by path. `triage-cvits` was the second ([ADR-0104](0104-triage-cvits-is-the-second-bundled-script-lint-gap-deferred-again.md)), and `glapi-test-pass` is the first whose script writes to a tracker.

We rejected leaving the logic as prose the model re-implements per run, which is how the skill worked before. Re-derived code is unversioned and untested: two runs of the same export could group or order findings differently, and the transform's traps — the second-precision target date that must be day-truncated before grouping, the manifest's two accepted forms — have no regression guard, so a later edit reintroduces a bug no test catches. A bundled script with a fixture freezes the transform as a contract: the selftest asserts the drafted body and the three-bin partition against a known input, and the skill stops tracking the model's run-to-run variation. This matches the discipline `write-skill` already names — a deterministic step is a black box the body should not re-explain — and follows the shape of the repo's existing `scripts/*-selftest.sh` convention, used until now only for repo infrastructure (lint, install): the selftest sources `scripts/selftest-lib.sh`, drives a fixture, and reports the three-state exit. `lint-skills.sh` fails a bundled `.sh` or `.py` script with no selftest beside it, and `pre-commit` runs the paired selftest when the script or its fixtures are staged (`scripts/README.md` § Run the selftest of what you touched).

The portable unit stays "skill + declared deps" from [ADR-0007](0007-self-contained-skill-bundles.md) as [ADR-0016](0016-behavior-skills-declared-deps-relaxed-atomicity.md) amended it: a bundled script travels inside the skill directory, so a skill that installs by symlink carries its script and selftest with it, no new install step and no shared library to resolve.

A bundled script makes no tracker write that a user-invoked publisher owns. `/to-story`, `/to-tasks`, `/to-feature` and `/to-bug` are the write path for work items, and all four are user-invoked, so a human types each one ([ADR-0106](0106-admit-the-cvit-skills-as-org-bound.md) records it for the CVIT skills); a script that created or updated a Story itself would be a side channel around them. So the two CVIT scripts stay **thin and side-effect-free**: data in, data out, no `az` call and no network, and the body prints each publisher command for a human to type. What the script owns there is the pure transform between the export and the drafted body; what the body owns is deciding which Story each finding maps to.

A user-invoked skill whose whole job is one fixed sequence of tracker writes that no publisher owns may run those writes from its script. `glapi-test-pass` is that case. It creates a Test Case, a requirement suite, a test run and a Passed result so that the GLAPI production deployment gate finds a passing test point on a User Story, and no publisher drafts any of those. Before the script, the model ran the same `az` calls itself, copied from about 7 KB of shell in the body, and each call needed IDs the previous one returned. The script now makes the calls, and its selftest pins each one against a fake `az` on `PATH`. The typed command is the ask for the writes, as it was when the model ran them, and the result's comment says that no test was run and names the PR or pipeline run that was checked. Nick decided this in the 2026-10-12 round: grill Q29 cleared the record as compliant (the GLAPI team owns the gate, and his team makes the call), and the 2026-10-16 follow-up narrowed this record's boundary to the publishers.

## Considered Options

- **Re-derive the logic as prose each run (prior state)** — no new files; rejected because the transform is unversioned, untested, and free to vary run to run, with its two known traps unguarded.
- **Extract the logic to a shared repo-level `scripts/` library** — one home for all skill logic; rejected because it breaks the symlink-live bundle — a skill would no longer install self-contained — for a transform only one skill uses.
- **Bundle a tested script in the skill's own `scripts/` (chosen)** — the transform is versioned, fixture-tested, and travels with the skill; sets the precedent a second such skill follows.
- **Keep every tracker write out of a bundled script, `glapi-test-pass` included** — rejected: the rule protects the publishers, and the gate record's writes bypass none of them, while keeping them as prose leaves a sequence of up to 14 calls untested and replayed by hand.

## Accepted difference — the Story HTML is not byte-identical to the oracle

The Story HTML these drafts become through `/to-story`'s pandoc differs cosmetically from the hand-patched oracle Stories — the oracle carries unquoted `id=problem` attributes and a trailing space before some close tags (`Problem </h2>`), artifacts of the pandoc version that produced them. The drafted markdown is the contract; its pandoc output is HTML-equivalent and renders identically in Azure DevOps, so the skill does not post-process the HTML to reproduce those bytes. The one byte that *is* reproduced, because it is visible content rather than markup cosmetics, is the non-breaking space after "vs." in the Out-of-scope paragraph — carried as a literal U+00A0 in the script and pinned by the selftest.

## Revisit when:

A second skill needs the same transform, at which point a shared library under the repo's `scripts/` earns the move this record rejected for a single consumer; or a publisher comes to own a write a bundled script makes, at which point that write moves to the publisher.
