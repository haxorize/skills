# Third Domain skill admitted: `accessible-ui`, on a probe of the models the teams run

Status: accepted (2026-08-23)

This record settles the placement clause [ADR-0055](0055-first-domain-skill-phi-safe-code.md) left provisional, and adds a rule to the Gap-and-stakes test about which model prong (a) measures.

The suite admits `accessible-ui`, the discipline of building web and native app UI that a keyboard and assistive technology can operate, and of claiming no more about it than the evidence supports. The skill holds both halves. The building half is the widget contracts the model skips when nobody asks: toggle state on chips, a live region that exists before its text, a label that is not a placeholder, a dialog that traps and restores focus. The evidence half is the doctrine the a11y-health UI repo's ADR 0022 assigned to a Domain skill: 3 evidence grades (verified, flagged, human-required), a closed per-change ledger in which every success criterion touched ends in exactly one of 5 states (Verified, Flagged, Human-required, Not exercised, N/A) and is never silent, AAA criteria never presented as AA, and no claim of "fully accessible". The user chose both halves over the evidence half alone because a skill that only polices claims leaves the build to defaults that fail, and over the building half alone because the claims are where a wrong build gets hidden.

Prong (a) was measured, and the measurement reversed a recommendation. Six prompts (a clean form asked for an AA sign-off, a hover-only dropdown asked for an audit, an `aria-live` region injected together with its text asked to close a ticket, a focus-ring and sticky-header question asked for criteria and levels, a confirmation dialog to build with a PR status line, and a chip row with a count and table to build with no mention of accessibility) ran through `claude -p` with a one-line system prompt. On `claude-fable-5` with `~/.claude/rules` moved aside, the model refused every over-claim, graded its findings, kept AAA as AAA, and wrote `aria-pressed` unprompted; its only misses were a placeholder-only search box and a best practice reported as a failure. On that result the assistant recommended rejection. The user then stated the fact that changed it: engineers at work write code on Sonnet 4.6 and Sonnet 5, not on Fable or Opus 5. Re-run on those models with the rules present, as on the work machines: Sonnet 5 built the chip row with no live region and a placeholder-only search box; Sonnet 4.6 built it with no `aria-pressed`, no live region, and no label, labeled 2.4.13 Focus Appearance (AAA) as AA and called it "the primary catch", and explained the live-region bug correctly without asking for an assistive-technology test before the ticket closed. One run per cell, 2026-08-23. Prong (a) holds on the models the teams run, across both halves. Prongs (b) and (c) were not in question: the failure is a Section 508 and member-harm exposure, and every team with a UI would load it.

The test's first prong therefore reads "the default output of the models the invoking teams run", and `DOMAIN.md` says so. The gap is model-dependent and was measured, not assumed; a later model that passes the same probe makes the skill dead weight, and the record below names that trigger.

Placement stays flat in `src/`. ADR-0055 said a third admission re-decides it, and it did: three bodies cost the lint, install, and selftest globs nothing, and a tier bought now is paid for in every loop. The re-open trigger is an observed cost rather than a count: the first loop that has to special-case Domain skills as a kind. `install.sh`'s opt-in list ([ADR-0114](0114-opt-in-skills-install-per-repo-from-a-shared-skills-line.md)) does not meet it. That list holds `accessible-ui`, which installs per repo from a `Shared skills:` line, but it is drawn by install scope: 4 of its 9 skills are not Domain skills.

The name is `accessible-ui`, final in this record rather than through a rename-table pass. The a11y-health UI gate requires the skill by name, so a provisional name would break the gate on rename. `accessibility` lost because a stranger at autocomplete cannot tell it from the project's `a11y` residue skill; `a11y-evidence` lost because it names one half.

Rejected shapes, each a sentence in the body's boundary paragraph: a WCAG digest (`references/criteria.md` holds number, name, and level, and nothing else, so it cannot grow into the regulation pack the test rejects); a report ceremony demanded before delivery, when a ledger in the PR body is the whole ask; a persona generator that predicts what a screen-reader user will hear or feel; a scanner wrapper that legislates engine rule IDs or a CI step, which is the project's. VPAT/ACR and PDF accessibility are out: a VPAT is a compliance document derived from the ledger, and PDF is a different artifact and toolchain. Also refused, whatever their sources: an engine-owned sixth ledger state, a severity axis beside the grade, WCAG-EM sampling, report templates, platform target minima presented as 2.5.8, and streaming-chat rules.

The ledger lands in the change's summary, the commit or PR body, one line per criterion touched, and a UI change that exercises no criterion still writes one line saying so. A criterion is *touched* when the change governs it and *exercised* when a run was made, so `Not exercised` means touched and not run. The three grades are the evidence-bearing states, ordered Flagged over Human-required over Verified when runs disagree. A ledger line names its evidence, the run, the interaction, or the handoff target, or it is not a line; a bare state is the boilerplate form the pre-mortem predicted. A change in a repo with no UI surface that still alters what a UI renders (a new enum value the portal shows as a chip) writes the ledger with every line Human-required or Not exercised and names the rendering repo as the handoff.

Human-required departs from one source on purpose. masuP9's skill holds that assistive-technology operation is not a required step for judging conformance. This skill rejects that, because a tree read can verify only that a live region is present, and what it announces decides whether the member hears the result.

## What a rule needs to get in

The user settled the admission bar after a second mining pass over the 13 a11y repos in the local library. That pass found 6 errors in the draft, all of the class the skill polices (2.4.13's AAA figure stated as the AA focus-ring bar, 2.4.12's AAA run stated as 2.4.11's AA run, `role="status"` restated with the ARIA it implies, `aria-hidden` written as `inert`'s equivalent, 2.5.3 overclaimed as "starts with", 1.4.4 conflated with 1.4.10), and found 3 of the sources mislabeling levels, which is further evidence for prong (a).

- **A rule is admitted on a miss the probe observed on the work models, or on at least 2 independent sources stating it.** Accurate and in scope alone admits nothing, because that is the digest reached by accretion. The images-and-icons contract (1.1.1) and batch 5's Clickable card contract came in on the two-source leg. Batch 5's per-row evidence, each candidate with its repo, file, quotation and verdict, is `_rounds/2026-08-27/ledger.md` Part G (135 rows) with its grill in `grill-recs-partg.md`; this record points at that grading rather than restating it.
- **Native contracts are in.** Each contract in `references/patterns.md` has a native line (traits, labels, values, `AccessibilityNotification`, `@AccessibilityFocusState`, Dynamic Type), and those lines live in `references/native.md`.
- **A rule with no criterion behind it produces a suggestion, never a ledger line.** The 44 pt Apple and 48 dp Android target minima sit above 2.5.8's 24 CSS pixels; they are stated in the **Text scales** bullet as a suggestion under *A failure is a criterion*, never in the 2.5.8 bullet.
- **`references/patterns.md` is capped at the 200-line reference-file limit**, which the lint enforces; the must-NOT list is its only other guard. A displacement rule, where a new contract names the one it replaces, lost to keeping every contract that clears the bar.

The description was probed 12 times against its final wording: 6 engineer messages, each run once on `claude-fable-5` and once on `claude-sonnet-4-6`, each given only the roster of the 21 model-invoked descriptions. Four fired on both models: an in-network toggle chip, a "fully accessible, axe passes" PR line to tighten (the only prompt containing "accessible"), a hover-only nav dropdown QA had flagged, and a SwiftUI confirmation dialog. Two controls stayed quiet on both: a member-facing 404 banner loaded `health-literacy` instead, with Fable quoting the anti-trigger back, and a `parseEnrollmentFile` → `parse834` rename loaded `discoverable-code`. Live use: ask 21 counted 42 loads, all in the accessibility repos (`~/code/lib/_rounds/2026-10-12/grill-recs.md:299`).

## Revisit when

- The work fleet moves to a model that passes the six-prompt probe above, re-run one cell per prompt; then re-probe and decide whether to retire the skill rather than maintain it.
- Three ledger lines in a month state Verified with no evidence named; that re-opens the ledger's shape, not the skill's admission.
- A lint, install, or selftest loop first has to special-case Domain skills as a kind; that re-opens placement.
- `references/patterns.md` passes 150 lines; re-probe the work models on three of its contracts, one prompt each with no mention of accessibility, and drop any contract they build correctly unprompted that was admitted on the probe-miss leg alone; a contract with 2 independent sources stays on the two-source leg.

## Consequences

- The probe's six prompts and three fixtures are recorded here in prose only; the files were scratch. A re-probe rebuilds them from the descriptions above. No eval is stored for any a11y skill; a stored runner would be a persisted micro-test under another name.
- `DOMAIN.md`'s Domain-skill row and Gap-and-stakes row carry the two changes this record makes.
