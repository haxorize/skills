# Mine 12 new repos and 19 deltas; port discoverable-code, fold the rest

The 2026-08-14 round cloned 12 previously unseen repos, delta-fetched the 19 already in the ledger, and read 5 URL sources (tpope and cbea.ms on commit messages, Google's developer style guide, Addy Osmani's "Agentic Code Quality", and a copywriting thread whose source went unrecorded and which yielded nothing — marketing copy, outside this suite's scope). One candidate justified a whole skill and 60 landed as fragments folded into existing ones. We took `discoverable-code` as a skill rather than a fold because its rules only cohere as a discipline, and we folded everything else because a fragment that can be stated as a clause inside a rule the suite already carries does not earn a load. None of the 12 repos becomes a lineage upstream under [ADR-0034](0034-branch-mining-lineage-or-dormant-main.md) except dmmulroy/dotfiles, which does — it is now `discoverable-code`'s upstream, and future sweeps diff it the way they diff mattpocock/skills.

## Why discoverable-code is a skill

dmmulroy's `write-discoverable-code` (`home/.agents/skills/write-discoverable-code/SKILL.md` @ aae3dd3) starts from a premise no skill in the suite held: an agent navigates by plain-text search, so every identifier is a search query and every miss costs reads. The rules that follow — 2–4 word exported names with a domain word, one definition site, whole string literals instead of template-built event names, unique error-message prefixes, a plain-words phrase in the doc comment so natural-language greps land, no bare-role filenames — are individually small and collectively a stance. Folding them into `codebase-design` was the alternative we rejected: that skill judges depth at an interface, and naming-for-search is orthogonal to depth (a deep module can carry an ungreppable name, a shallow one a perfect name). Folding them into `tdd` or `implement` would have made them fire only on the build path, when renaming, reviewing, and reading want them too. The skill takes dmmulroy's durable-vocabulary rule from a second file (`coding-standards/references/comments-and-jsdoc.md`, same SHA): planning-era names — `Phase2Handler`, `NewCheckoutService` — stay in planning material and never reach a public name. We dropped the upstream's measured uniqueness statistics on adoption, as we did with gsd-core's in the [ADR-0046](0046-four-repo-fragment-mine.md) round: the 3-word knee argues for itself without an unpublished monorepo count behind it.

Two further drops are deliberate. The upstream's §2 on types — branded primitive IDs, capability-token parameters, discriminated unions in place of nullable clusters — stays out entirely, because those decide which states are representable, and that is `codebase-design`'s question rather than a findability one. Only §2's last rule crossed over, since naming a type the way a compiler error will quote it is a rule about what the agent reads back. The durable-vocabulary rule crossed over narrowed: upstream binds names, public documentation, UI copy, and rendered errors, while the port binds names alone. UI copy answers to `writing-for-humans`' microcopy register, and rendered errors are already governed here by the unique-prefix rule, so the wider scope would have duplicated two owners.

Three skills declare the new behavior, each at the point where a name gets written or read back: `tdd` in its refactor beat, `implement` on the direct path where `tdd` never runs, and `review-changes` as the conditional Discoverability lens. The skill's own description keeps its trigger list rather than shedding the clause `requires:` already implies, which is the opposite of the trim `domain-modeling`'s description took this round. The asymmetry is intended: a `requires:` edge resolves the dependency for the declaring orchestrator, but it never fires the behavior for a model reaching it directly, and `discoverable-code` is meant to be reachable that way.

## What was folded, by cluster

Authoring gains the wind tunnel — simulated-use testing with a quarantined wielder, a scenario mix, and a transcript rubric — plus live-failure-becomes-standing-scenario, crash-resumable state for stateful skills, an exclusion-spec row in the form-to-failure table for output that honors a stated bound while smuggling in what the bound existed to exclude, and a lint gate that resolves every relative `.md` link a shipped skill file claims, so a pointer at a missing reference fails loudly instead of loading nothing.
- **Human-facing prose** (`writing-for-humans`, `tell-catalog.md`, `ship`): modality-is-content, which resolves the standing tension between the hedge-stack tell and the preservation contract — deleting a hedge changes the claim, so it is a rewrite, not a trim; deliverable purity (a produced artifact ships bare); the audit-slop register, scoped to human-facing prose only; the retrospective-neatness tell; the context-isolated cold read; timeless docs; number-carries-method; the anaphora and three-single-sentence-paragraph tells; the aphorism-rate tell; a README first-screen row; the first-line/last-line read on the session-summary and incident-report register row; form-fix-cannot-rescue-substance; and cbea.ms's "If applied, this commit will ___" test in `ship`'s commit style.
- **Interview and verification** (`grilling`, `verify-docs`): named dwell, which makes staying on a fuzzy answer an announced move rather than a stall; two refusals — the grill wanted as a blessing, and the grill on a decision already locked, where the loop exists so the plan can be seen to have been challenged; the ownership-versus-craft-gate split, which says whose call a disputed item is. `verify-docs` gains source-map faithfulness — ground each load-bearing claim of a derived doc in a source passage or a decision, never memory — and bidirectional drift, so a doc stricter than its source reads as invented doctrine rather than caution.
- **Prototyping and handoff** (`prototype`, `handoff`): named directions on a declared divergence axis, never Option A/B/C; the tradeoff table with the choice left to the user and converged variants cut out loud; a riff round around the picked direction; fidelity-follows-the-dimension. `handoff` plans carry a `git rev-parse` stamp, and the executor stops and reports on drift instead of improvising.
- **Review and tests** (`review-changes`, `finding-discipline.md`, `tdd`, `audit-tests`, `diagnosing-bugs`): reviewer subagents never dispatch reviewers; a trust-model briefing for the security lens where the repo records boundaries; a post-fix review base named out loud, since reviewing from the pre-fix base and reviewing the fix commits alone are both legitimate and an unstated choice leaves the reader unable to tell reviewed-and-clean from never-looked-at; a dismissing mitigation held to the same evidence bar as the finding it dismisses. Test-side: the flake-fix ban with a soak through the former failure mode; the degraded-verdict shape for fallback branches; near-miss allow fixtures that test a pattern gate in both directions; a property-test trigger for changed invariants; SDK-style interfaces over generic fetchers.
- **Build and design** (`implement`, `codebase-design`, `improve-design`, `feedback-loops`, `capturing-learnings`): the one-way ceremony ratchet, where reaching for a lighter label to skip work is itself the doubt that forces the heavier path; the model-seam principle (code owns control flow, identity, validation, and merges; a model gets a contained judgment behind a typed seam); no compatibility layer added to shrink a diff or appease old tests, only for a named live reader; fix the generator rather than hand-patching generated output; the `tail`/`head` ban with file-first capture; never fabricate tooling; a can't-get-worse baseline paired with incremental cleanup; a rejected-candidates section on advisory scans; and a retention test for memory stores.
- **Small folds**: `domain-modeling`'s description loses a clause `requires:` already covers; `ship` refuses a closing keyword against an already-closed issue; the ADR trade-off gate gains the opposite test (the rejected alternative must be one a rational actor could pick); `wait-what` gains a smallest-view repertoire for its visual re-pitch; `wizard` writes human-run procedures in the fewest steps that still work.

## Rejections that generalize

- **Working redundancy is not cruft** (anthropics): directly opposed to this repo's pruning discipline and its review-time pruning pass. Adopting it would have licensed the duplication those exist to remove.
- **Batch "approve all" on a review queue** (swyx): reintroduces the false yes `grilling` bans.
- **Cross-model second opinions** (deepsec): agreement between readings is not evidence, so a second model's concurrence raises nothing.
- **One ask per message** (asmartbear): conflicts with the frontier round, where a grill asks every question whose prerequisites are settled. It survives as a `wizard`-only consideration, since a human at a terminal answers one prompt at a time.
- **An ADR-write trigger on `domain-modeling`** (mattpocock): crosses the split [ADR-0015](0015-model-invoked-vs-user-invoked-split.md) and [ADR-0021](0021-keep-adr-standalone-not-absorbed-into-domain-modeling.md) drew between recording decisions and maintaining vocabulary.
- **Never invent commands** (openclaw): the suite deliberately infers a command and marks the inference when no config states one.
- **Bold as a skimming channel** (attention-span): the bold-decoration tell already rules bold to naming duty only.

## Consequences

Sixty fragments is larger than the 38 of the [ADR-0046](0046-four-repo-fragment-mine.md) round, counted the same way — per digest entry, with several entries landing as more than one rule — and dilution was again the named failure mode. Three guards bound the build. Fragments fold into existing rules by default, with lint's size caps a hard stop: a fragment that cannot land without pushing its host past 200 lines comes back as a named cut. Three earned sections of their own instead — `verify-docs`' derived-document pass, `write-skill`'s rules for skills that keep state across sessions, and the wind tunnel in `testing-skills.md`. Each is a procedure the reader runs rather than a clause sharpening a rule its host already carried, and folding a procedure into a neighbouring paragraph buries it. The audit-slop register is scoped to human-facing prose, because `evidence`, `boundary`, and `surface` are load-bearing words in this repo's own skill bodies and an unscoped tell row would sand them out. The wind tunnel is an offered testing leg, never a mandatory gate, so authoring a small skill does not acquire a simulation cost.

Reversal is the costly direction, as in the prior rounds: the folds carry no per-fragment markers, so unwinding one means recovering it from this record and the diff. The cluster list above is therefore exhaustive rather than illustrative.
