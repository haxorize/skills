# Skills are judged by the Team-fit test; the retire-on-zero window binds stubs only, and an unused skill exits to a shelf on the team lead's call

The 2026-08-21 round tied retirement to fire counts: [ADR-0051](0051-usage-evidence-mining-round.md) scheduled a retire check on `validate-behavior` and a flip-to-user-invoked check on `adoption-verdict`, [ADR-0056](0056-first-off-path-skill-change-quiz.md) put every Off-path skill on a retire-on-zero window, and [ADR-0058](0058-grill-me-absorbs-grill-and-record.md) put the `grill-and-record` stub on one. In the 2026-08-27 grill Nick decided that a count is not the criterion. The skills serve a product engineering team, and teammates' sessions are on machines nobody measures, so a zero on this machine or the work machine is evidence about load, never a verdict about use.

A skill is admitted and kept by the **Team-fit test** (`DOMAIN.md`): its deciding record names a concrete moment in a product engineering team's work and the role who hits it, and it is retired only when an existing skill or global rule already serves that moment. Fire counts are evidence for the case. The call is the team lead's, stated in the record. `audit-skills` is the single home of the check. Its Keep verdict names the moment and the role, its Retire verdict names what serves the moment instead, and its Overlap lens is the covered-by half, reaching `~/.claude/rules/` as well as other skills. Its fifth dimension, **Usage**, takes the counts from `scripts/skill-usage.sh`: typed `/name` invocations from `~/.claude/history.jsonl` and model `Skill` loads parsed as the assistant `tool_use` block over every transcript under `~/.claude/projects/`. The script takes `--since` and `--exclude-session`, prints a `+` floor marker on any run that met a truncated transcript, and its selftest grades the two hand-count traps (gate text and a probe's `"skill":` string) as non-loads. The two columns measure different axes: the first run, over this machine's August window, found `ship` typed 44 times and loaded 0, and `committing` typed 0 and loaded 29. The retire-on-zero window survives for Deprecation stubs alone, because a stub serves one person's muscle memory and that person's typing history is the whole population. The stub window starts the day the stub landed and reads every machine the typist works from, one at a time.

The test had no way out for a skill nobody runs. Fourteen skills were admitted between 2026-08-27 and 2026-10-12 and none left (`git log --diff-filter=A` and `--diff-filter=D` over `src/*/SKILL.md`), so each unused one added lint time and review-sweep work for good. In the 2026-10-12 grill Nick gave it an **exit** (grill Q17). A skill becomes a **shelf candidate** when it reads 0 typed and 0 loaded on this machine **and** on the work machine, each from one `scripts/skill-usage.sh` run (the work figure pasted by Nick when the round opens), in two consecutive Mining rounds at least six weeks apart, and was admitted at least six weeks before the first of them. The candidate comes to Nick in that round's grill, and he decides, so the count still nominates and the call stays the team lead's. A skill whose moment arrives without warning is exempt (`respond-to-incident`): nobody gets the notice that a `git mv` back needs, while a departure or a rewrite is announced weeks ahead. A model-invoked zero first takes a description trim or a flip to user-invoked, and is shelved only when neither can work.

A shelved skill moves to **`shelf/<name>/`**, a sibling of `src/`. It is not installed (`scripts/install.sh` links only `src/*/`), linted, routed by `which-skill`, listed in `README.md`'s map, synced to the work mirror, or diffed by `docs/lineage.md` sweeps. It stays in git, and returning it is `git mv shelf/<name> src/<name>` plus its router and README rows, then lint.

Five alternatives were weighed. Keeping the window as written was rejected because its population is unmeasured for every real skill. Dropping the window entirely was rejected because a stub's typist is known, so its count is sound. An admission-only or retirement-only test was rejected because the first lets four skills serve one moment and the second never admits anything new. Keeping Team-fit with no exit was rejected because nothing ever leaves for want of use. Deleting a candidate rather than shelving it was rejected because a teammate who did use it is then owed an archaeology dig instead of one move. This amends ADR-0051, ADR-0056 and ADR-0058: their count-driven checks no longer run, and each record carries a pointer here.

## Consequences

- ADR-0051's one still-open check is canceled: the `validate-behavior` retire check, which its 2026-08-26 window kept open for a second zero. `validate-behavior` stays (the moment: an engineer proving a change works in the running app, not in tests). The `adoption-verdict` flip check was already closed on 2026-08-26 by [ADR-0032](0032-adoption-verdict-standalone-behavior.md) — one observed model-reached load settled the axis — so this record restates the Team-fit case for the axis it holds (the moment arrives as a question in prose, often from a teammate who does not know the suite exists). The `grill-and-record` stub is a Deprecation stub and closed on its own count.
- `onboard-me` was admitted on this test ([ADR-0064](0064-onboard-me-read-only-kt-session.md)), and `rebuild-contract` and `offboard-engineer` under their own records, each naming its moment and role.
- The clause-level retire hedges readers attach to folds ("retire on a window with no bare `UNVERIFIED:`") are dropped; a clause is kept or cut by the pruning test at review.
- **The exit clock** runs for audit-aeo, audit-tests, chart-course, delete-dead-code, glapi-test-pass, review-architecture, to-feature and product-description, and for report-progress and roll-out from 2026-11-08, six weeks after both were admitted on 2026-09-27. The first round that can apply the exit falls on or after 2026-10-24 (grill Q18 (b)), and the six skills that grill proposed to shelve waited for it until 2026-10-17, when Nick shelved none of them this round: each is user-invoked, so its description costs no per-turn bytes. `respond-to-incident` is exempt. `debrief` is off the clock, since the retrospective skill replaces it (grill Q3), and `ask-for-me` is off it, since it folds into `writing-for-humans` (grill Q19).
- **`resolving-merge-conflicts` is the first skill on the shelf**, by Nick's direct call on 2026-10-17 rather than through the exit, so the trim-or-flip step was skipped. It read 0 typed and 0 loaded on this machine (`scripts/skill-usage.sh`; the work machine was not counted), and as a model-invoked skill its 292 B description was paid on every turn (the lint's model-invoked catalog went from 11,503 B to 11,211 B). The 2026-10-12 grill had kept it until a no-skill run on a scripted rebase showed whether the model copes alone (round register D1); that run never happened, and the shelving closes D1 without it. Its `docs/lineage.md` credit row stays, since the MIT line it credits is still in git under `shelf/`.
- `audit-skills` gains a **Shelve** verdict beside Retire, and `DOMAIN.md`'s Team-fit row carries the exit; **Shelf** is defined there.

## Deferred

- `scripts/skill-usage.sh` counts typed and Skill-loaded uses only, not a subagent's Read of a `SKILL.md` by path, so a skill reached that way reads zero. The exit is not applied until the script carries a by-path read column with its selftest (round register D45).
- Whether the teammate who joined about 2026-08-31 used `onboard-me` is Nick's to ask before the first round that applies the exit (round register D44).

Revisit when: teammates' usage becomes measurable (a shared transcript corpus on the work machine). Counts would then serve the covered-by half as evidence, and the exit would read every teammate's machine rather than two.
