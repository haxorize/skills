# The commit-msg hook checks message shape, and deliberately not register

Status: accepted (2026-08-28)

The house commit style was being missed in practice. `committing` holds the rule, but the style itself lives one link away in `references/commit-style.md`, and reaching it takes two soft steps: the model has to reach for the skill on its description, then follow the link. The failure has a name in `DOMAIN.md` — **load suppression**: a rule that lives behind a pointer loses to the pointer's own summary of it, so the agent reads the paraphrase, finds it workable, and never opens the file. No load gate reaches this, and not only because `committing` is **model-invoked** and so has no caller to hold one; a load gate guards a *skill* load, and what was skipped here is a *reference-file read* one step further in.

The honest form of "was being missed" is a measurement, not an anecdote. Run over this repo's own history, the exact rules reject 90 of 386 messages, and 5 of the last 40 — the breakdown is under *Consequences*. No dated incident was logged when the hook was proposed, which is a gap against the ladder [ADR-0051](0051-usage-evidence-mining-round.md) records: prose, then hard prohibition, then hook or lint, each rung earned by an observed failure. The measurement is the evidence this rung actually rests on, and it was taken after the fact.

So we added `scripts/git-hooks/commit-msg`, which rejects a message breaking the exact rules and names the reference file in the rejection, so the block is also the load instruction. It is the watcher a model-invoked skill cannot carry, and it plays the part the `review-receipt` **Hook** plays one layer down, though it is a **git hook** and not a PreToolUse one: neither can judge quality, both force the step to have happened.

**The gate.** *Surprising without context* — clears: the obvious reading of a style checker is that it checks the style, and this one deliberately checks less than half of it. *Real trade-off* — clears: the alternative was leaving the rule prose-only and strengthening the load path instead, which a rational team would pick to avoid a checker that gives false assurance. *Hard to reverse* — clears, though it is the weakest of the three: the file deletes in a second, but the decision does not live in the file. `core.hooksPath` is per-clone and uncommitted, so withdrawing the hook means finding every clone that ran `setup-hooks.sh` and every mirror it was synced into, none of which is enumerable from here; and a repo that has been committing under the gate for a while has a history shaped by it, so removing it silently re-admits the drift this measured. All three, so this is its own record. (An earlier draft of this section scored it two of three and wrote the record anyway. `adr/SKILL.md` says all three must hold and `adr-format.md` says stop if one is missing — there is no two-of-three threshold in this repo, and a record that waives its own admission test teaches the next author that the gate is advisory.)

**What it does not check, on purpose.** One logical change per subject, whether the body's *why* was non-obvious enough to need writing, the register, and the entries in `writing-for-humans`' `tell-catalog.md` that no pattern can reach — **Tricolon habit** (a shape you can only see by counting enumerations across a whole message), **Retrospective neatness** (a causal history tidier than the work actually was, which requires knowing what the work was), and **Audit-slop register** (where the same word — "evidence", "surface", "contract" — is correct in an agent-facing rule file and wrong in prose written for a person, so the verdict is entirely contextual). Those need a reader. A hook that appeared to cover them would be worse than none.

Note what this does *not* claim. Much of the catalog **is** greppable — **Empty emphasis** and **Faux-insight setup** are fixed-string lists, no harder to match than the code fence this hook already rejects. The line between the halves is not "shape is mechanical and register is human"; it is narrower and less flattering: some register tells are literal strings and could be checked, and are not, because a rejection is an expensive interruption and a false positive on a legitimate "really" would cost more than the tell does. That is a threshold judgment about interruption cost, not a claim about machine-checkability, and it should be re-argued rather than inherited if the hook ever grows a warning channel that does not block.

**So the style doc is not pruned against it.** `writing-for-agents`' **Scaffolding** rule says a rule the tooling enforces is a cache of that enforcement, which would normally license trimming the prose once a checker exists. That rule holds only where the check fails the exact violation, and here it fails a strict subset. The hook's own header and `CLAUDE.md` both say so, because the pruning pressure will recur every time someone reads the two side by side — amended: see Amendments 2026-08-30.

**Why this does not reopen [ADR-0059](0059-review-receipt-hook.md)'s rejection.** That record considered gating `git commit` for the *review receipt* and rejected it: "it would block the fix-up commits `address-findings` produces after the review; the push is the act that leaves the machine." The rejection stands and is not disturbed here, because it turned on *what* was being gated. A receipt is a claim about a whole tree, so checking it per commit blocks legitimate intermediate states; message shape is a property of the single commit being made, has no intermediate state to block, and is worthless at push time when the message is already written. The two gates sit at the layer each one's subject actually exists at. This does mean `address-findings`' fix-up commits now pass a gate — a shape gate, which they must pass anyway.

**A git hook rather than a Claude Code hook.** A `PreToolUse` hook on Bash — the shape the three hooks under `global/hooks/` take — sees only what is on the command line, so a message supplied through an editor or a file is invisible to it. The `commit-msg` hook sees the final message however it arrived. It also covers commits made by hand, not only the agent's. `commit-bypass.sh` already blocks `--no-verify`, so this layer was agent-proof before it was written.

**This hook is fail-closed, and the other three are not.** `hook-lib.sh` states the posture for the PreToolUse hooks: "a safety hook that blocks on its own errors trains the user to disable it", and ADR-0054 extends it to any non-zero exit. This one runs under `set -uo pipefail` with no allow-with-breadcrumb path, so an internal error aborts the commit. That is deliberate and is the first recorded exception: a PreToolUse hook that fails open loses one check on one command, while a commit-msg hook that fails open silently admits the message it was built to inspect, and the author has no signal that anything was skipped. The cost is that a future unbound variable blocks commits rather than warning — which is loud, recoverable in one edit, and graded by the self-test.

**The imperative-opener check warns rather than blocks**, because it is a wordlist heuristic over the "Added/Adds/Updated/Fixes" family and will sometimes be wrong about a legitimate subject. Every other rule is exact and blocks.

## Consequences

- This amends [ADR-0049](0049-opt-in-post-merge-hook-auto-runs-install.md), which defined `setup-hooks.sh` as the opt-in for "an opt-in `post-merge` hook": `bash scripts/setup-hooks.sh` now enables two git hooks, not one, with materially different blast radii — one warns after a pull, one blocks a commit. It also amends [ADR-0052](0052-committing-extracted-from-ship.md), narrowing its claim that a model-invoked description was the only mechanism reaching a commit made with no skill loaded; this hook is a second one. Opting in for auto-hoist also starts rejecting commit messages — the README and `setup-hooks.sh`'s own output both say so, the script because it is the last thing a person sees before the behavior starts.
- Measured against the repo's own history at the time of writing, the hook rejects 90 of 386 messages — 23%, and 5 of the last 40. Almost all of those are the **wrap** rule, on body lines 73 to 75 columns wide and subjects 73 to 74: the ambient habit has been off by one to three columns for the repo's whole life and nothing measured it before. Expect the wrap rule, not the register half, to be the rejection you actually meet.
- **The gate is porous, and this is not a claim to enforcement.** `commit-msg` is invoked by `git commit` and by the commit concluding a merge. It is *not* invoked by `git cherry-pick` (with or without `-e`), `git revert` (with or without `--edit`), or a plain `git rebase` replay — verified on git 2.50.1 — so a message those operations bring in or replay is never checked. Inside `rebase -i`, coverage is per-verb: `reword` fires the hook, `squash` does not. The reachable escape is `git config --local --unset core.hooksPath`, which disables every hook in the clone at once, silently and stickily; `commit-bypass.sh` blocks the `-c core.hooksPath=` form but not that one.
- The hook is inert until that opt-in runs; `core.hooksPath` is per-clone and uncommitted, so the work-machine mirror needs its own.
- Writing the self-test found a live defect the hook shipped with for an hour: the git-comment strip used a BRE alternation BSD `sed` does not support, so on macOS it never stripped anything. A short comment line violates no rule, which is why the first fixture passed either way. Making the fixture's comment lines long enough to trip the wrap rule turned an inert row into a graded one and surfaced the bug — the argument for grading a check by mutation rather than by reading it.

## Considered Options

- **Leave it prose-only and strengthen the load path** — rejected: the load path is the thing that failed, and every available strengthening is another pointer.
- **`prepare-commit-msg` instead** — rejected, but it is the closest call. It runs *before* the author writes and could seed the buffer with the style pointer, which fits "the block is also the load instruction" better than a rejection does, since it teaches before the mistake rather than after. It cannot reject, so it is a complement, not a replacement; worth adding if rejections turn out to be the interruption this record is betting they are not.
- **A `pre-push` range check** — rejected for now, and it is the only shape that closes the porosity below. `commit-msg` is not invoked by `cherry-pick`, `revert`, or a plain `rebase` replay, so any of those can land a message this gate would reject. A `pre-push` check over the range would see all of them, at the layer ADR-0059 already chose for exactly this reason. Rejected only on scope: it is a second gate with its own opt-in and self-test.
- **A check inside `lint-skills.sh` or the `post-merge` gates** — rejected: both run after the fact, and neither can reject the commit that caused the problem.
- **Extending the hook to the greppable register tells** — rejected under the threshold argument above, and revisitable if a non-blocking warning channel appears.

## Revisit when:

`commit-style.md`'s exact rules change; or a non-blocking warning channel appears, which reopens the threshold judgment above for the greppable register tells; or a message this gate would reject reaches `main` through cherry-pick, revert, or rebase replay, which is the evidence that the `pre-push` range check has stopped being optional.
