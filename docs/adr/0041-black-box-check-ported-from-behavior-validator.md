# black-box-check ported from openclaw's behavior-validator

> **Amended by [ADR-0063](0063-team-fit-test-replaces-retire-on-zero-window.md):** the second-zero retire check scheduled in the amendments below is canceled. `validate-behavior` is kept on the Team-fit test — the moment is an engineer proving a change works in the running app — and a **Skill** carries no retire-on-zero window; the window binds Deprecation stubs alone.
> **Amended by [ADR-0057](0057-rename-table-and-discipline-skill-term.md):** `black-box-check` is renamed `validate-behavior` in that record's rename table; the reason given here for the original name no longer holds, since the same record renames the skill kind Discipline skill.
> **Amended by [ADR-0075](0075-transcript-sourced-mining-round.md):** the ceremony question the 2026-08-27 amendment below leaves open is put and left open — five `validate-behavior` clauses land, two of them raising the precondition cost (ADR-0075's 2026-08-30 amendment), and `U6`, the one clause that adds a step before the first user task, waited on one measured run against `a11y-health-ui` that counts the precondition turns — run 2026-09-04, `U6` REJECT (Amendments, 2026-09-04, later).

Nothing in the suite validated the *running* artifact — `audit-tests` audits the test suite, `review-changes` judges the diff, `feedback-loops` runs checks that already exist — so a UI that only prints success text could pass every gate. openclaw/agent-skills' behavior-validator fills that gap with a discipline that only holds as a whole skill: validation against a behavior contract written *before* testing, source-blindness as a hard rule (implementation-looking evidence is contamination that halts the run), and anti-cheat probes that catch fake or static behavior. We ported it as the user-invoked `black-box-check` (2026-08-08 mining round), trimming the JSON report schema and the workspace-isolation ritual to house prose-report style. We rejected folding just the anti-cheat probes into `audit-tests` — the probes are only trustworthy *because* the contract predates the run and the checker can't read the code's story about itself; splitting them from that identity leaves decoration, not discipline. We renamed it because "behavior" already names a skill kind in this repo's domain language.
