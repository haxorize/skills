# black-box-check ported from openclaw's behavior-validator

Nothing in the suite validated the *running* artifact — `audit-tests` audits the test suite, `review-changes` judges the diff, `feedback-loops` runs checks that already exist — so a UI that only prints success text could pass every gate. openclaw/agent-skills' behavior-validator fills that gap with a discipline that only holds as a whole skill: validation against a behavior contract written *before* testing, source-blindness as a hard rule (implementation-looking evidence is contamination that halts the run), and anti-cheat probes that catch fake or static behavior. We ported it as the user-invoked `black-box-check` (2026-08-08 mining round), trimming the JSON report schema and the workspace-isolation ritual to house prose-report style. Folding just the anti-cheat probes into `audit-tests` was rejected — the probes are only trustworthy *because* the contract predates the run and the checker can't read the code's story about itself; splitting them from that identity leaves decoration, not discipline. Renamed because "behavior" already names a skill kind in this repo's domain language.
