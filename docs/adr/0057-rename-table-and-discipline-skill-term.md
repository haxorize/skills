# One rename table over every skill name; the glossary term becomes Discipline skill

Status: accepted (2026-08-22)

The 2026-08-21 mining round left naming decisions scattered across three records and a ledger: [ADR-0051](0051-usage-evidence-mining-round.md) decided `black-box-check` → `validate-behavior`, [ADR-0055](0055-first-domain-skill-phi-safe-code.md) and [ADR-0056](0056-first-off-path-skill-change-quiz.md) each deferred a working name, and the plan carried a glossary rename with no evidence either way. This record is the one place those were judged, as a table over all 44 skills then in `src/` (`ls src | wc -l`) plus the 3 provisional names — 47 rows — on one criterion: a stranger reading `/` autocomplete — engineers and product or BA roles alike — recognizes a user-invoked name, while a model-invoked name keeps trigger fidelity because no human types it. Ported skills keep their upstream name only where the port is near-direct and the name vendor-neutral (the ECC adaptation criterion, ledger A40.A21). Pairs-only naming in `DOMAIN.md` held: no Discipline skill lost its gerund and no Orchestrator gained one. Nick decided every row; the grill put the counter-case on each.

The names this record changed were chosen in six other records, and each links back here. [ADR-0041](0041-black-box-check-ported-from-behavior-validator.md) and [ADR-0043](0043-wait-what-ported-name-kept.md) chose the two names the table retires. [ADR-0015](0015-model-invoked-vs-user-invoked-split.md) and [ADR-0018](0018-design-quality-and-project-aware-review.md) carry `review-architecture` and `sweep-domain`, [ADR-0051](0051-usage-evidence-mining-round.md) the Discipline-skill term, and [ADR-0070](0070-offboard-me-handover-in-repo-human-as-evidence.md) `offboard-engineer`. No lint checks these back-links (`scripts/lint-adrs.sh` reads no amend mention), so this list is the enumeration.

## The table

- **Renamed (3).** `black-box-check` → `validate-behavior`: ADR-0051's decision stands. The counter-case was `ledger.md` row D11's: the skill was on a retire-on-zero window, and the rename would spend edits on a name that might go. It lost because a name should say what the skill does. Retirement is now judged on the Team-fit test, not a fire count ([ADR-0063](0063-team-fit-test-replaces-retire-on-zero-window.md)), and the skill is kept on it. `wait-what` → `explain`: the skill has a cold-topic branch (`/explain <topic>`, the surviving idea from Anthropic's `eli5` plugin; its picture-artifact form stays rejected, ledger A31.8), and `wait-what` presupposes a confusion the cold ask does not have. A40.A21 stops protecting a port name once the body grows a mode, and the name `explain` stood when the branch landed. `change-quiz` → `merge-quiz`: the quiz is the gating half and "before merging" is the moment ADR-0056 names; `change-quiz` read as a quiz about change in the abstract. `catch-me-up` lost because it names the report half and hides the gate.
- **Final as proposed (2).** `phi-safe-code` and `health-literacy` (the B10 skill, unnamed until this table). Both are model-invoked Domain skills, so the description carries the triggers and the name carries the domain noun. `plain-language` lost for `health-literacy` because it names no domain, and `member-copy` because it is one payer's word for the reader.
- **Kept (42).** Every other name then in `src/`. Alternatives were tried for the rows that gave the stranger pause — `wizard` (`human-steps`, `manual-steps`), `harden-domain` (`refresh-glossary`), `address-findings` (`fix-findings`, `act-on-review`), `glapi-test-pass` (`glapi-gate`) — and each was a sideways move: `refresh-glossary` breaks the visible `domain-modeling` pairing, `fix-findings` overclaims since findings get declined, `wizard` is a near-direct neutral port. A rename the criterion does not demand is churn on typed muscle memory. `harden-domain` was later renamed on other grounds, below.
- **Not stubbed.** Neither of the two renamed skills then in `src/` gets a deprecation stub: `grep -rl '"/<name>' ~/.claude/projects | wc -l` found 0 transcript files for `/wait-what` and 0 for `/black-box-check`. `/grill-and-record` had 13 and got a stub when `grill-me` absorbed it ([ADR-0058](0058-grill-me-absorbs-grill-and-record.md)). The cost a rename cannot undo is typed muscle memory, and these two names had none.

## Names judged after the table

The tightening round's renames go through this table ([ADR-0077](0077-tightening-round-one-house-style.md), which also records the naming convention for new skills). Nick decided each of these:

- **`harden-domain` → `sweep-domain`.** "Harden" appeared only in the name and H1. The body's first sentence and `DOMAIN.md`'s **Sweep mode** row already named the act, and "hardens/hardening" carries a different live sense elsewhere in the suite.
- **`offboard-me` → `offboard-engineer`.** The `-me` suffix read as the person typing, which the manager-run frame contradicts. The artifact follows: `docs/handover/` → `docs/offboarding/`, `handover.md` → `offboarding.md`, and the **Handover** term → **Offboarding record**, which dissolves the one-letter Handoff/Handover ambiguity.
- **`improve-design` → `review-architecture`.** The old name promised an act the read-only body refuses. "Architecture" leads its description and keeps it apart from a UI-design reading, which nothing in the suite owns.
- **Declined.** `evaluation-ledger` and `rebuild-contract` keep their names on the noun-name ruling: a user-invoked skill may carry a noun name when the noun is its registered artifact, the ground that already protects `adr`. `verify-docs` and `doc-claims` both stay, with their seam carried by a routing line and a `DOMAIN.md` flagged-ambiguity row. The verb-symmetry and scope-token nominations became flagged-ambiguity rows instead.
- **No stubs for the three, by waiver.** `~/.claude/history.jsonl` held 4 typed `/harden-domain`, 6 typed `/improve-design`, and 0 typed `/offboard-me`. The Deprecation stub row gives no stub to a name nobody typed, which covers only `offboard-me`. The other two had earned stubs on that row, so Nick's waiver overrides the rule, and the row says a waiver can be recorded against it.

Names judged at admission, on the stranger-at-autocomplete criterion:

- **`upgrade-deps` (not `deps-upgrade`) and `sweep-corpus` (not `corpus-sweep`).** A user-invoked orchestrator should read as a command beside the verb-first orchestrators it sits with (`sweep-domain`, `verify-docs`, `validate-behavior`). A noun-first name (`dependency-upgrade`) reads as an upstream's, and this skill was authored, not ported. The criterion is not "every user-invoked skill is verb-first": `wizard`, `handoff`, `prototype`, and the noun-name ruling's `adr` are not. Neither rejected string had been typed, so neither got a stub.
- **`doc-claims`.** The verb-first pull binds user-invoked orchestrators, which a stranger meets in `/` autocomplete. A Discipline skill is met in a `requires:` line and in the router's parenthetical, so it takes the [artifact]-[aspect] shape of its neighbors (`work-item-shape`, `codebase-design`). `grounded-docs` matches the property-naming family (`phi-safe-code`, `discoverable-code`, `health-literacy`), but it reads naturally only for derived documents and strains for one checked against code. `doc-drift` is the most legible to a stranger but too narrow, since an UNSUPPORTED claim is true today and has not drifted. The `doc-` prefix carries weight: `claim` means an 837 insurance claim in two Domain skills here, so a bare `claim-*` name would collide. The name was the user's call on a recommendation.
- **`accessible-ui`**, judged in [ADR-0060](0060-third-domain-skill-accessible-ui.md), which declined `accessibility` and `a11y-evidence`.

## The glossary term

**Behavior skill** becomes **Discipline skill**, with `Behavior skill` kept as the listed alias. The plan's reason (`ledger.md` row D10) was that "behavior" collides with the product-behavior sense, and `validate-behavior` makes the collision a skill name. The measurement that settled it, at `f4e6d56` with `grep -rIio '\b<word>\b' src/*/SKILL.md | wc -l`: skill bodies say "discipline" 31 times when describing what they hold (`grilling`: "the relentless-interview discipline"; `domain-modeling`: "the active discipline") and "behavior" 136 times, almost all meaning the thing under test. The term was the odd one out in the repo's own prose. The grill's first recommendation was to keep the term because the churn looked larger than the gain; on the count (`git grep -i -o 'behavior skill' | wc -l`) it is 20 occurrences in 5 files, four of them ADRs that stay as written, and churn is not a naming criterion.

The bare shorthand "the `X` behavior" for a Discipline skill is banned in the alias column, and `write-skill`'s "Behavior vs orchestrator" heading is gone. `grep -rIn 'the \`[a-z/-]*\` behavior\b' src DOMAIN.md README.md CLAUDE.md` returns nothing. The same pattern over `docs/`, excluding this record, finds 3 lines in older records, which the sweep left alone. The sweep renamed a label and moved no skill body's rules.

## When names are judged

A name is judged at admission, at retirement, and when the skill's body gains or loses a mode — the `explain` case. It is not re-judged each mining round. This rule exists so "Names" does not recur as a batch that re-opens every row each round; the must-NOT probe found nothing else forbidding it. Retirement is a Team-fit call ([ADR-0063](0063-team-fit-test-replaces-retire-on-zero-window.md)), not a count.
