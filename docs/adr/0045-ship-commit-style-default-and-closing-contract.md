# ship gains a house commit style and a closing-comment contract

`ship` told the drafter to match the project's style and, where nothing was documented, to "say so once" — which left the actual gap case, a repo with thin or inconsistent history, with no floor at all. The 2026-08-08 mining round's phase 6 (mcollina/skills `a88a866`, openai/skills `49f948f`, posthog/ai-plugin `13dd2e2`, pbakaus/agent-reviews `ee827ae`, tbhb/vale-ai-tells `233bd55`, mathews-tom/agent-armory `d9ef25b`, msitarzewski/agency-agents `ebe9c99`) supplied the floor. We put the **house commit style** in `src/ship/references/commit-style.md` — at first as the evidence-gated fallback applied only after the project's own conventions came up empty. Project style still won everywhere it existed, and the gate was explicit: before declaring the history inconsistent, ship had to cite two or three recent subjects as the evidence — the pre-mortem failure this guarded was the default steamrolling a real but undocumented house style. The style itself is mcollina-shaped plain-imperative, not Conventional Commits: an imperative subject aiming ~50 characters (hard 72), no type prefix, no trailing period; a body only when the subject cannot carry the *why* (body length is a function of non-obviousness, never of diff size); body ordered previous behavior → observable consequence → why this change is correct. We rejected Conventional Commits as the default because it is a convention the drafter would be importing into repos that never adopted it — where a repo uses it, project-style-wins already applies it, and only there does armory's BREAKING-trigger enumeration bind (public API signatures, removed or renamed exports, config schema, CLI flags, non-additive stored-data schema ⇒ the `!`/footer is mandatory).

We adjudicated the PR-body contradiction between the sources deliberately. mcollina's rule wins as the default shape: **the PR description is the commit body plus links** — no `## Summary`/`## Testing` headings on a routine PR, structure only where a genuinely complex change needs it to be reviewable. The fallback `## Why`/`## What Changed` headings from openai/skills' `yeet` lose, but its separable content rules are adopted on top:

- an existing repo PR template always wins over the no-headings default (adapt it, answer `N/A` where a section doesn't apply, never delete its sections);
- the body describes the net diff, never work attempted and undone along the way;
- verification content is opt-in — included only when there is behavioral evidence worth preserving for a reviewer (a repro, a before/after run, a targeted scenario), never generic lint/type-check/CI output.

posthog's evidence block generalizes into the claims rule's sharpest edge: a measurable claim (performance, error rate, benchmark) carries the exact command and verbatim numbers, or it does not get written.

Two split principles join step 2 from the same sources: **one attributable claim per commit** (posthog's exam-and-answer rule — a commit that changes a check and the code it validates proves nothing), and **every commit leaves the tree consistent** (armory's bisectability, adopted as a shaping principle for the split, not a mandate to run the suite per commit).

The closing comment gets a contract: what landed with the commit SHAs or PR link, status checked per the claims rule, the remainder — anything deliberately not done or descoped — named plainly, and closure verified by re-reading the ticket state. msitarzewski's ticket-ID gate extends ship's existing refusal to invent a pointer: an ID is used exactly as provided — never invented, normalized, or guessed — wherever it appears (commit message, branch name, closing comment).

Placement splits by kind, so tell ownership does not fork. The *structural* rules live in ship's reference file. The *register tells* join `writing-for-humans`' tell catalog as a commit-and-PR family, with a matching register row in its register-by-artifact table: commit self-narration ("This commit adds…"), trailing justification ("…ensuring consistency"), hedging about a change already made ("This should fix…"), file-by-file listing, test enumeration ("all 47 tests pass"), changelog-style headings inside a commit body, the shipping-specific marketing adjectives, solution-shaped filler, and the copy-pasted issue text mcollina's review guide flags. ship already `requires: writing-for-humans`, so the tells fire without new wiring, and any future skill that drafts a commit inherits them for free. pbakaus's reply contract lands in `receiving-review`, not ship: outcome-per-thread replies on PR review comments (every comment answered; "Fixed in `<hash>`" cites the commit that actually contains the fix, so the reply follows the commit; a thread is resolved only when the reply legitimately closes it — a fresh fix leaves the thread open for the reviewer to verify). That skill owns the loop of acting on findings, and replies are that loop's last beat — they routinely happen mid-review, long before ship runs.

Rejected: armory's Conventional-Commits mandate and `<type>/<slug>` branch naming (conflicts with ship's `<ticket>-<slug>`); `changelog-composer` wholesale, audience filter included (no changelog artifact exists anywhere in the flow — no consumer); Node-specific DCO sign-off, trailer machinery, and `core-validate-commit` (single-project ceremony); mcollina's `octocat` blanket ban on AI co-authorship attribution (the harness deliberately stamps `Co-Authored-By` and session trailers — the ban would fight host policy, and attribution is the host's call, not the skill's); and `yeet`'s `git add -A` plus auto-draft-PR mechanics (ship proposes a split and stages deliberately; blanket staging is the opposite of a proposed split).

## Amendments

- **2026-08-08, later the same day** — We promoted the house style from evidence-gated fallback to the default. Matching the project's undeclared history made mimicry the primary path and the good shape the exception, and the evidence gate existed only to protect that inference step — both go. Precedence is now two-tier: a convention the project *explicitly declares* (a style block in `CLAUDE.md` or `CONTRIBUTING`, a commit-lint configuration, a PR template) wins, because ignoring an enforced convention means failing CI and rejected PRs; everything else gets the house style, with no per-commit remark about the difference. The pre-mortem the gate guarded — the default steamrolling a real but unwritten house style — is now accepted deliberately: an unwritten convention that matters is a convention the project should declare, and the consistency of this drafter's output beats archaeology of the log. This amends ADR-0036's consequence that per-repo style stays in each consuming repo's CLAUDE.md; that record carries the matching pointer.
- **2026-08-21** — [ADR-0052](0052-committing-extracted-from-ship.md) moves the house commit style, the claims rule, and the closing-comment contract out of `ship` into the model-invoked `committing`, which `ship` requires. `commit-style.md` now lives at `src/committing/references/`; the `requires: writing-for-humans` wiring this record leaned on is `committing`'s. The style itself is unchanged.
