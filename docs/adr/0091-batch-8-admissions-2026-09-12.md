**The hook's shape, and why `Stop` and not session end.** The grill said "session-end hook"; the hooks reference (`code.claude.com/docs/en/hooks`, read 2026-09-13) says "`SessionEnd` hooks have no decision control. They can't block session termination" and that their JSON output fields are discarded, while `Stop` "can control whether Claude continues" with a top-level `{"decision":"block","reason":…}`; the same page documents `hookSpecificOutput` with `hookEventName: "Stop"` only for `additionalContext`, so the `decision` the hook also emits under that key is a belt-and-braces spelling the docs do not show, and the top-level form is the one that blocks. The same page says the transcript "isn't guaranteed to include the final message at Stop time on all versions", which is the lag the header's catch-a-turn-late paragraph accounts for. `Stop` fires after every agent turn, so a once-per-session guard would fire on the first turn before any correction exists; `global/hooks/friction-log.sh` instead keeps a per-session cursor (`.seen/<session-id>` beside the log) and hands the agent one instruction only when a user turn since the cursor matches one of twelve correction signals or is a denied tool call with guidance. It never writes the log, never grades, never proposes; `stop_hook_active` is the loop guard; fail-open with a breadcrumb on every error; no opt-in. The transcript is written asynchronously and may lag the turn (hooks reference), so a lagging correction is caught one Stop late, never lost. `scripts/install.sh` now reads an `# Event:` header line and prints the snippet grouped by event, a Stop entry taking no matcher; `install-selftest.sh` clean after the change, and the snippet parsed against an empty home (two events, three PreToolUse entries and one Stop entry, no `matcher` key on the Stop entry).

**What was tested, and what stands untested.** `friction-log-selftest.sh` runs 42 throwaway transcripts: one firing instance per signal and one quiet neighbor each, assistant and sidechain and meta turns quiet, the cursor silencing a rerun and re-arming on appended lines, the loop guard, six malformed payloads, a missing transcript, an unwritable cursor directory, and the line-shape equality with `src/debrief/SKILL.md`. ## Considered Options

- **Keep the name `retro`.** Rejected at the write: not verb-first, fails the stranger test, and `DOMAIN.md`'s Debrief row (`:403`) avoids "Retrospective" for the ceremony sense.
- **A `SessionEnd` hook, as the grill's wording said.** Rejected: it cannot hand the agent an instruction ("`SessionEnd` hooks have no decision control", hooks reference, read 2026-09-13), so the line would have to be written by a script with no judgment — which is the fallback below, not the design.
- **The hook writes the line itself from the matched text.** Rejected for now: a regex-written line names no rule and no tool, and the skill's Gate would open every such line onto a transcript read; kept as the fallback if the live false-positive rate makes the agent step too noisy.
- **Skip the debrief step; the round reads the log and opens transcripts itself.** Rejected on argument, not evidence: a round reads dozens of lines and cannot afford the git-dating and second-instance work per line, and a debrief written days later still has the transcript on disk where a round months later may not. The next round is the test, and the `Revisit when:` line names it.
- **The log under the round directory (`~/code/lib/_rounds/friction/`).** Rejected by Nick 2026-09-13: that path exists on one machine.
- **Detect corrections every prompt, capture positive signals, score confidence, auto-promote on recurrence.** Rejected as the standing classes the round refuses: machinery serving the agent, not a team.
