# AEO

Answer engine optimization treats AI assistants, answer engines, and agentic browsers as the newest assistive technology: a public page owes them the same base layer it owes a screen reader — semantically clean, server-rendered, accurately structured content — and most of the rules below are accessibility obligations the page already carries, stated with the precision an agent needs. The stakes are member-facing: a copay or benefit an engine extracts wrong is a member-harm and trust problem with regulatory adjacency, not a marketing miss. Every engine-specific claim in this skill carries its date and source, because engines and agent standards move quarterly; **re-verify anything here older than two quarters against the operator's current page before acting on it**, and write the date beside any such claim you add.

## The served DOM is the contract

The contract a page keeps with an agent is the HTML the server sends, not what a browser builds from it: the strict reading of any page is a fetch with no JavaScript executed, and every fact a person needs — the plan name, the premium, the copay, the deductible, the network, the phone number — is present in that response as text. Google's JavaScript guidance (December 2025) holds that canonical, robots meta, and structured data must be identical in the raw HTML and the rendered output, since either may be read; most retrieval agents and on-demand fetchers never render at all, so a fact that appears only after a script runs contributes nothing to their answers.

- **Never serve an agent a different page than a person gets.** No cloaking by user agent, no AI-only shadow site that drifts from the canonical HTML, no Markdown mirror that says something the page does not. Divergent content is the one shortcut that gets a domain removed outright, and a drifted mirror is a wrong answer with your name on it. Prerendering counts only when every client gets the same HTML; prerendering for bots alone is dynamic rendering, a workaround Google's guidance declines to recommend, and the same divergence. A client-rendered shell's strict reading is its `noscript` text: the plans listing's says shopping needs JavaScript, and that is the page an agent extracts.
- **One H1, no skipped heading levels, landmarks in the order a reader meets them.** An agent walks the heading outline the way a screen-reader user does; a page whose only H1 is the site name has no subject.
- **Link text names its destination; URLs are stable and canonical.** "Learn more" is a dead link to an agent choosing what to fetch next. A URL that changes per session or carries state an agent cannot reproduce is a page it cannot return to or cite.
- **A page has a size budget.** Googlebot reads the first 2 MB of HTML; single-fetch agents truncate or silently discard oversized pages. Inline base64 images and inline scripts push the structured data and the facts below the cut. Measure the served bytes, and keep the facts above them.
- **Media has a text alternative that carries the same facts** — a transcript for a video, the table for a chart image. Text in an image is text no agent reads.

## Structured data declares only what the prose carries

JSON-LD is a claim about the visible page, and an agent cross-checks it. Every property maps to content a person can see on the page, or it is a labeled placeholder; a material fact whose only machine-readable form is JSON-LD with no prose counterpart is a defect, and a schema type that declares a structure the page does not carry (a FAQPage whose questions are not on the page, an ItemList with no list) is worse than no markup. Google's AI features guidance (updated 2026-05-15) states there is no special schema.org markup to add for generative AI search; eligibility is ordinary Search eligibility. The block is in the served HTML: one a tag manager or route script inserts is absent from the strict pass and reads as missing to every agent that never renders. While a page's prose is still client-rendered, a JSON-LD block built from the same source at the same build is the interim that recovers extraction, labeled likely, never stable: a fetcher that strips script blocks sees nothing.

- **Baseline per page:** Organization and BreadcrumbList; WebSite with SearchAction on the home page; Article fields (headline, author, datePublished, dateModified, publisher, mainEntityOfPage) on dated editorial pages.
- **FAQPage is dated.** Google retired FAQ rich results for all sites on 2026-05-07; any non-Google extraction benefit is contested. Keep existing FAQPage where the questions are visible on the page and never claim a citation benefit for it; use QAPage only for genuine question-and-answer content; never recommend HowTo, deprecated September 2023.
- **Health-plan types** (schema.org's insurance and health-plan vocabulary) go on a page only where they are compliant for regulated content and a named consumer demonstrably reads them; the reference prototype is where they are evaluated, never a production page first.
- **dateModified is honest.** Bumping it without a content change is a lie that costs trust once an engine compares versions. A visible "last updated" date beside the fact is what an agent quotes.

## Extraction shape: the fact once, near its heading, in plain text

What an engine lifts is a self-contained passage; what it confuses is a fact spread across a heading, a footnote, and a tooltip. This section owns the shape of the content, not the words, which are `health-literacy`'s.

- **Lead each section with its answer** in a self-contained passage of roughly 40 to 60 words that survives being quoted alone. Phrase the heading as the question the section answers when the page exists to answer it.
- **Tables are data.** A benefit or plan-comparison table has a caption, scoped header cells, one fact per cell, and no merged cells; a table built from divs or an image is not a table to an agent.
- **One term per concept across the site.** An agent reconciling "copay", "co-payment", and "cost share" across pages reconciles them wrong; the glossary the site uses is the glossary every page uses.
- **A number travels with its attribution and date in the same sentence** — a footnote does not survive extraction. "Our data" loses its referent the moment it is quoted; name the source.
- **A section stays under roughly 375 words per heading.** Past that, a retrieval chunk cuts mid-fact; three such sections on a page drop its structure grade.
- **A question-and-answer block is structured as one** — the question as a heading or `dt`, the answer as the passage under it, not a disclosure widget whose text is absent until clicked.

## Crawl and access policy: decided per agent class, never per user-agent string

The front door is co-owned: bot management (the WAF, robots.txt, rate limits) belongs to security engineering, and the access policy is a joint artifact — let verified agents in, keep bad actors out. Every allow, block, or rate-limit decision names which class it applies to, because the classes have different consequences and are routinely confused in both directions.

- **Four classes:** training crawlers (build a model; blocking one is a legitimate, separate decision that changes no answer today), search and assistant indexers (retrieval; blocking one removes the site from live answers), on-demand user-triggered fetchers (a person asked the assistant to open this page; these ignore robots.txt by design and are controlled server-side), and agentic browsers (a person's agent operating the page). The per-operator names, as read on 2026-09-12, are in [references/agent-classes.md](references/agent-classes.md); open it when writing or reviewing a robots.txt, WAF, or bot-management rule, and verify each name against the operator's current documentation first, because the list ages.
- **A blocked retrieval crawler produces no error, only silence.** The signal is absence: the site stops appearing in assistant answers, and nothing in any log says why. So a request to "block the AI bots" is read as naming the training class until the requester says otherwise, and before an indexer line ships, the reply states which assistant answers the site leaves — ChatGPT search for OAI-SearchBot, Copilot for Bingbot, Perplexity for PerplexityBot — and asks whether that is the decision. A sign-off on "not giving our content to AI companies" is not a sign-off on leaving their answers; a closing change window does not make it one, and shipping the indexer lines as a fast-follow question is shipping the silence.
- **A user-agent string is not an identity.** A rule keyed on the string admits any spoofer and blocks nobody who lies; a manual fetch with a spoofed string tests a response path, not what the named vendor's crawler receives. Verify by the operator's published IP ranges, reverse DNS, or Web Bot Auth (RFC 9421 request signatures, emerging in 2026), and report a bot as allowed, blocked, or unverified from origin logs and WAF behavior, never from the string alone.
- **robots.txt is verified per bot by fetch, never assumed.** Read it as blocks: a Disallow belongs to the User-agent line above it, and `*` applies only where no bot-specific block exists. A non-200, a redirect off HTTPS, or a fetch failure is "unverified, with the reason", never "open".
- **Google-Extended opts out of Gemini training only**; Googlebot serves Search, AI Overviews, and AI Mode alike, so blocking the first changes no answer and blocking the second removes the site from all three.

## Actions and feeds are exposed on purpose, and authenticated access is another program

An agent handles a plan finder gated behind interactive controls poorly, and the fix is rarely to make the controls cleverer: expose the same task as something an agent can address — a URL that names the result set, a data feed a fetch returns whole, a documented action. Real `button` and `a` elements with associated labels, prices and specifications visible as text, and a layout that holds still are the agentic-browsing baseline; Lighthouse's agentic-browsing category (13.3 and later) reports a fractional pass ratio, and its findings are opportunities to surface, not a gate. The access policy names which feeds and actions are exposed, to which classes, at what rate.

Commerce protocols — agentic checkout and payment specifications, card-network agent tokens — are a watch item as of 2026-09-13, not a commitment: record which assistant ecosystems consume each before building to it, and re-date this paragraph when one does.

Authenticated agent access — an agent acting for a logged-in member — is out of this skill's scope on purpose. It is an agent-identity, consent, and HIPAA program in its own right, chartered separately; a public-page decision that quietly assumes it (a feed that would carry member data, an action that needs a session) is raised as that program's question, not built here.

## llms.txt and Markdown mirrors: publish cheaply, never grade or claim

No major answer engine has publicly committed to consuming llms.txt, and Google's AI features guidance (updated 2026-05-15) says verbatim that no new machine-readable files, AI text files, markup, or Markdown are needed to appear in generative AI search. Publish an llms.txt at low priority if the cost is an afternoon; never present it as a ranking or citation factor, never grade a page on its presence, and say exactly this in any report so nobody quotes the file later as a proven lever. A Markdown alternate of a page is served at an explicit URL, linked with `rel="alternate"`, never through content negotiation: negotiating on Accept needs a correct Vary header on both representations, and a framework that rewrites Vary ships a CDN cache handing the wrong representation to the wrong client.

## Every engine claim is dated and every score is advisory

- **A recommendation carries a confidence label:** stable (a published standard or policy, or visible evidence), likely (current practice, platform-dependent), inferred (reasoned, not verified), or disputed (conflicting or unofficial). llms.txt guidance is likely or disputed, never stable; a served-DOM rule is stable.
- **A performance claim cites field data at p75 or is `UNVERIFIABLE`.** Core Web Vitals are field evidence (CrUX, PageSpeed), never an editorial grade; a single fetch's timing is a server proxy, and a site with no field data says so.
- **Never promise a citation, a ranking, or an AI outcome.** A page can pass every check and be absent from every answer; a readiness score says the page is extractable, not that it will be extracted.
- **A fix is written literally** — the JSON-LD block, the exact meta element, the heading outline — never described. A finding cites what was fetched, with the date and the fetch conditions; nothing is audited from memory.
- **An extraction measurement runs more than once and reports its variance.** A model answering from fetched content is not deterministic; a single run is an anecdote. A wrong extracted fact scores below an absent one, because a confident wrong answer costs more than silence.

## Boundary

**Share-of-voice, visibility, citation rate, and AI-referral traffic** are marketing's outcomes on this foundation; this skill enables their measurement and owns none of them. **Rank tracking, keyword research, backlinks, programmatic page generation, and local-listing tactics** are SEO tooling and never enter here; the technical readiness layer is the shared ground, and AI-SEO is not a third term. **What the words say** is `health-literacy`'s; **how the prose reads** is `writing-for-humans`'; **whether a person can operate the surface** is `accessible-ui`'s, and a rule here that is also a WCAG criterion is graded there. **What data may appear on the page** is `phi-safe-code`'s. **The evaluation of one page** is the user-invoked `audit-aeo`.
