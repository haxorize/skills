# What a model seam owes

Open this when a design places a language model at a seam: what the code keeps and the model gets, a model's write to user-owned data, what the model is sent, how it asks a person something mid-task, which of an agent's actions it may take unasked, or whether a judgment about people treats them alike.

- **The model seam.** Where the design puts a language model inside the system, the code keeps control flow, identity, validation, and merges; the model gets exactly one contained judgment behind a typed interface — defined input, defined output shape, a defined fallback for output that doesn't parse. Code selects, orders, and counts, and the model phrases: a list, an order, or a count a model assembles differs run to run, so the code builds it and the model words it. A model that classifies or reranks returns a label or score per item, and the code builds the list from those. The seam faces the other way too: a tool family the model calls answers in one shape across all its tools, so the model never fills a missing key with invention. This is the depth rule applied to a nondeterministic implementation: the seam is what lets the judgment be swapped, and what lets it be scored against a measured baseline instead of assessed by impression. A model that owns a merge or an identity decision produces behavior nobody can reproduce, test, or explain, because the part that decided is the part with no interface.
- **A model's write to user-owned data lands behind an accept.** A record, a note, a profile field: the model may propose and nothing more — the write lands as a diff behind an explicit accept, with the original preserved and an undo after accept. A "silent enrichment" that fills a user's field without that gate has taken the user's authorship, and is a finding on the change the same as a failed footgun test. A confirmation prompt is not that gate against an agent — an MCP path or a CLI driven with `yes |` answers it with no user present — and a risk tier names blast radius, never a gate. Scope the credential the agent runs under to what the accept would have permitted, so a write it cannot be asked about is one it cannot make.

- **Own the input as well as the output.** The judgment gets the smallest representation that answers it — a typed extract of the fields the decision reads, never the richest artifact at hand: a structured read of the page rather than a screenshot, three fields rather than the whole record. An input nobody chose is an interface nobody can test, since the baseline the seam is scored against moves with whatever the call happened to include.
- **Asking a person is a typed, resumable call.** When the model needs a human mid-task — an approval, a missing fact, a choice — it emits a typed request naming what is asked, the allowed answers, and how urgent it is, and the task parks with its state persisted until the answer arrives as an event. It never blocks on a prompt, and an unattended run never answers its own request. The accept on a write to user-owned data is one instance of this seam.
- **An agent's own actions sit on a floor and a ladder.** Place each action by reversibility and reach. A fixed set of irreversible or wide-reaching actions stays human-only under every setting, and no auto-approve mode lowers that floor, which the credential holds as it holds the accept above. Above the floor, autonomy is earned one explicit, visible, revocable step at a time — a one-off approval, then a standing rule, then an allowlist entry. Every action records its approval — auto-approved under which rule, approved by a person, or denied — kept with the run, so "why did it do that" still has an answer after the fact.
- **A judgment that reaches people is checked for equal treatment.** Where the judgment feeds a decision about a person — access to a service, a benefit, a price, or an outcome a protected characteristic must not predict — its fixture set holds inputs that differ only in what a protected characteristic would predict — names from several cultures and scripts, a spread of ages, an apostrophe, a hyphen — and the check is per pair: two inputs that differ only in that characteristic get the same outcome, and any pair that differs is a finding. Where the judgment is also scored on a population, a group whose favorable-outcome rate falls below 80% of the highest group's rate is a finding too. A correct output shape on every fixture is not this check.
