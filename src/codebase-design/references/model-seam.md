# What a model seam owes beyond its output

Open this when a design places a language model at a seam and the question reaches past the output shape and the write gate: what the model is sent, how it asks a person something mid-task, which of an agent's actions it may take unasked, or whether a judgment about people treats them alike.

- **Own the input as well as the output.** The judgment gets the smallest representation that answers it — a typed extract of the fields the decision reads, never the richest artifact at hand: a structured read of the page rather than a screenshot, three fields rather than the whole record. An input nobody chose is an interface nobody can test, since the baseline the seam is scored against moves with whatever the call happened to include.
- **Asking a person is a typed, resumable call.** When the model needs a human mid-task — an approval, a missing fact, a choice — it emits a typed request naming what is asked, the allowed answers, and how urgent it is, and the task parks with its state persisted until the answer arrives as an event. It never blocks on a prompt, and an unattended run never answers its own request. The accept on a write to user-owned data is one instance of this seam.
- **An agent's own actions sit on a floor and a ladder.** Place each action by reversibility and reach. A fixed set of irreversible or wide-reaching actions stays human-only under every setting, and no auto-approve mode lowers that floor, which the credential holds as it holds `SKILL.md`'s accept. Above the floor, autonomy is earned one explicit, visible, revocable step at a time — a one-off approval, then a standing rule, then an allowlist entry. Every action records its approval — auto-approved under which rule, approved by a person, or denied — kept with the run, so "why did it do that" still has an answer after the fact.
- **A judgment that reaches people is checked for equal treatment.** Where the judgment feeds a decision about a person — access to a service, a benefit, a price, or an outcome a protected characteristic must not predict — its fixture set holds inputs that differ only in what a protected characteristic would predict — names from several cultures and scripts, a spread of ages, an apostrophe, a hyphen — and the check is per pair: two inputs that differ only in that characteristic get the same outcome, and any pair that differs is a finding. Where the judgment is also scored on a population, a group whose favorable-outcome rate falls below 80% of the highest group's rate is a finding too. A correct output shape on every fixture is not this check.
