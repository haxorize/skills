# Fanning out the lenses

Opened from §3 only when the diff exceeds the in-process threshold — more than 5 files, or any code hunk. A small prose-only diff runs its lenses in-process and never opens this file.

Run each **custom lens** (DOMAIN, ADR, AC, design depth, discoverability, smell baseline, verification gap, instruction-file, amendment bookends, falsification) as its own **read-only subagent** that returns *findings only* — keeps the caller's context clean. Built-ins that already self-parallelize (`/code-review`, `/security-review`) may run at top level rather than wrapped in a subagent.

**Every finder is briefed diff-only.** The handoff's narrative goes to the falsification lens alone (§2), run last, after the diff lenses return; every other finder judges the change without the author's framing, so the framing cannot steer it.

When a brief enumerates files, each must have its hunk in the brief; a file named without its hunk was not reviewed.

Before any prompt goes out, run the aggregate-sufficiency test from [subagent-brief.md](subagent-brief.md): if every lens did its brief well, would the aggregate be excellent? Then every fan-out prompt follows three rules:

- **Coverage-first.** Tell each lens to report everything it finds, severity and confidence attached — filtering is step 4's job, done here at the caller. Never write anti-noise hedges into a finder prompt ("don't pad the report", "only flag if you're certain"): scope-limiting phrasing suppresses real findings more than it suppresses noise. (The empty-return license in § Negative-space pass below is the one sanctioned exception — it licenses absence rather than suppressing findings.) Brief each finder with the stance that defects exist and its own named softenings — downgrading a Blocker to avoid seeming harsh, taking "tests pass" as correctness evidence, reading only the file under review. And every finder prompt carries §6's not-examined line requirement, so the coverage ledger gets its input from each return.
- **Carry the lens's material.** The smell-baseline prompt must include the catalog file (contents or path) — the subagent won't discover it on its own. The ADR-lens prompt likewise carries the applicable rulings themselves — a reviewer briefed with the ruling catches conformance drift an unbriefed one walks past; frame what-to-check from the ruling's text, never from the current code, and point at where to look, never at whether it conforms. The AC-lens prompt carries the **scope-reduction vocabulary** — the token list `work-item-shape`'s Sizing section owns; read it from there rather than re-typing it — cross-checked against the item's recorded decisions: a change can cite the decision it implements while delivering a fraction of it, and scope reduction is never a mere warning — the only resolutions are deliver fully or propose a split. And every finder prompt carries the Anchored-confidence section of [finding-discipline.md](finding-discipline.md) — the LOW/MED/HIGH definitions and the quote gate — so the confidence a finder attaches means what step 4 assumes it means.
- **Carry the rules subagents don't inherit** — quoted from [subagent-brief.md](subagent-brief.md). Its **Launch-failure classification** binds the caller: a lens never silently drops.

## Negative-space pass

After the vet, run one more read-only subagent that gets the diff *and* the vetted findings, told to hunt only where the findings did not go — the findings map where attention was spent; its value is everywhere else. An empty return is a good outcome, not a failed pass — but the global evidence rule binds it like any other negative: it names the regions it swept and the files it read, so the report can tell an examined empty from an unexamined one. A bare "nothing found" is the second. The pass is skipped on a diff that never opened this file, and on a mechanical one — renames, formatting, generated content.
