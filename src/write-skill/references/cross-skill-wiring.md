# Cross-skill wiring

How one skill names, calls, or depends on another — read when the edit in hand writes or reworks a reference that fires another skill (a `Skill` tool call, a `/<name>` suggestion, a `requires:` line, or a load gate), or when which of the three forms a new mention takes is not obvious; an edit that adds a bare-backtick mention you can already place does not open this. Phrase every firing reference with **two independent signals**:

- **Which form — *who fires it?*** How one skill names or calls another skill. Three forms, one meaning each; `DOMAIN.md`'s **Invocation form** row owns which form means what, and this bullet applies it. Write ``Call the Skill tool with `<name>` `` wherever the **model** fires the skill: a load-bearing delegation (`implement` → `tdd`), a lazy load (`domain-modeling` → `writing-for-humans`), or an ungated soft delegation, a model-invoked skill's own (`tdd` → `feedback-loops`). Write **`/<name>`** only where a **human types the command** — a suggestion of a user-invoked skill (`to-story` → "run `/grill-me` first") or a built-in (`/code-review`, `/simplify`); a bare `/<name>` aimed at the model asks it to type a command it cannot type, and lint fails one naming a model-invoked skill in any file the repo ships, `references/` included. Keep the plain backtick form where nothing fires: borrowed **vocabulary** ("a `codebase-design` problem"), a **boundary** ("treats recording as `adr`'s job"), a rule of a skill the body already loaded ("`work-item-shape`'s **Naming drift** rule"), or a **gated offer** you must not fire before the user consents (`implement` offers `adr`).
- **Which tier — *does the next step need its text?*** Name the tool wherever the next instruction cannot be carried out without the target's content in context — the body is about to write against rules only that skill holds. That covers a **load-bearing delegation** and a **lazy load** alike: both instruct a load, and the noun alone would leave the instruction with nothing to act on. Use the bare noun for an **opportunistic reference**, where the prose only names the register a trigger-rich skill reaches for on its own and nothing in the next step consults its text. Ask it of the *work*, never of the sentence: a test whose antecedent is how the sentence is already worded cannot decide how to word it. A tool call on a mere mention trains a spurious load and reads as a dangling instruction; a tool call on a gated offer jumps the gun.
- **Load gate vs none — *would a silent miss change what I produce?*** The gate ("if you don't see a `Launching skill: X` line, stop and call it again") needs **two** conditions, both of them. **Placement:** only inside a **user-invoked** skill, because the gate works by the human who typed the command seeing the load line. Never gate inside a model-invoked skill (no watcher, so a gate nobody reads fails silently — call the tool but don't gate; where the miss would be wrong-kind, that is an *ungated soft delegation*, and only the caller's own body can carry what the miss would cost), a human suggestion (the model can't invoke a user-invoked skill — its description is hidden), or a built-in command (`/code-review`, `/simplify` — always installed, no `requires:`). **Necessity:** only where a silent miss makes the caller emit the **wrong kind** of artifact, not merely a worse one — the target carries the caller's *method*, so stripping it leaves no procedure behind (`grill-me` → `grilling`, `ship` → `committing`). Name what the caller would produce with the target absent — reading the artifact off *this body's* own description of what it emits, not off what a good version would look like. If the body still prescribes every part of that artifact with the target gone, the miss is worse and not wrong-kind; the target is only carrying the caller's method where the body would be left with a part it cannot describe how to produce. Gate only if that thing is the wrong kind: `to-story` → `writing-for-humans` is a lazy load, because the item still publishes with the right shape in flatter prose, while `to-story` → `work-item-shape` is a gate, because the shape *is* the product. **Open the target before judging the caller** — what the body states inline can look like the whole standard until you read the skill and find the material the standard is decided by. And **check the argument's reach**: a ground that would gate every caller in the corpus is not a ground. "The output is prose of kind X" fits every prose-emitting skill, which is why it gates none of them; "the register change *is* the intervention, so a miss re-emits the artifact this skill was invoked to replace" fits `explain` and nothing else, which is why it gates. Name what the target supplies that this body cannot, then ask how many callers that naming fits — if the answer is all of them, you have described the corpus rather than this delegation. Ask it of the **work**: an unconditional imperative is how a gate is written, never evidence that one is warranted, and "the caller is user-invoked" is a permission to gate, never a reason to. A **conditional** delegation gates when its condition fires (`implement` → `diagnosing-bugs`, only on an unexplained red); a **repeat** delegation gates at the site where a miss does the damage, not only at the first mention.

So the form tracks *who fires it*, the gate tracks *verified*. A model-invoked skill's `requires:` deps stay ungated (and usually opportunistic — an auto-reached chain has no watcher).
