# Evidence travels with the claim

Depends: `committing`, `review-changes`, `implement`, `receiving-review`, `address-findings`, `upgrade-deps`, `handoff`, `writing-for-humans`

A claim in anything you produce — a status line, a count, a "done", a "tests pass", a report, a deferral — carries its evidence **beside the claim** — in the same message, or in the same artifact — or it carries a marker: `UNVERIFIED:` for a claim not checked, `UNVERIFIABLE` for a check this session cannot run. A confident sentence with no evidence and no marker is the failure.

- **The answer first, then the evidence.** A yes/no question gets "yes" or "no" in its first words, a count gets the number, and the command and output follow — never a paragraph the reader mines for the verdict. A yes with a caveat opens on the yes and the caveat follows — never a "No —" whose next clause concedes the point.
- **Re-measure every count at write time.** A number stated from memory is a guess wearing a number's clothes; the count comes with the command and its verbatim output, inline, once — that is the whole evidence, no proof blocks, no receipts, no command logs. A count measured through a limit (`head`, a Read cap, `grep -m`, a truncated tool result) is written `N+` with the limit named, never as a total.
- **Name your own corrections, and sweep the whole category.** When a number or claim you stated earlier turns out wrong, say "earlier I said 34; it is 17" — never restate the right figure as if it had always been so — and name the check that was skipped when the claim went out. Told that one count was wrong, re-measure every count in the message, including the ones used to check the others.
- **Inspection is not execution; dispatch is not completion.** "I ran X" means X ran in this session, and its output is what you cite — having read a test, a script, or a command is not having run it. A spawned agent's result is not evidence until it is in hand; a count or status written while a lens is still running is a guess about what it will return.
- **A check parses the way its consumer parses.** A hit on a pattern you spelled shows only that the search finds your spelling: the check reads the artifact as its consumer reads it (`git interpret-trailers`, not `grep '^Co-Authored-By:'`, for a trailer), or it is green exactly where the hole is.
- **A hit is not a read.** A claim that something exists, or does not, at a path is **read-confirmed** — the file opened, the line seen — or **name-matched** — a hit, or a miss, on a name. Name-matched reaches a report only as a hypothesis with its command attached: a shadowed definition, an alias, a dynamic reference, or a search root picked by guess defeats every grep, so where two files could match, both are opened, and "no usages" from a search alone is not a finding.
- **A claim about the transcript needs a transcript grep.** "You said", "we agreed", "as discussed" cite the turn. Memory of a conversation is the least reliable evidence in it.
- **After a command that exits 0 regardless, verify the effect, not the status.** `sed -i` on a pattern that matched nothing, `az boards work-item update` on a field it ignored, a `git push` to the branch that was already up to date: check the file, the item, the remote.
- **An empty or failed check is not a clean result.** A negative — "not found", "no callers", "nothing uses it" — names the command and the scope it searched, and a generalization drawn from it names the step that was not run. An empty search shows absence only once the same command, run in this session against a pattern you know is present, has returned that hit: a grep that has found nothing today has not shown it can find anything. Nor does an empty search refute someone else's claim: a citation not found means never verified, not false, and the claim is overturned by an attempt under the conditions it names. And a check whose command never ran — auth, network, a missing tool — gets its own line marked `UNVERIFIABLE`, naming what would run it, and never the clean outcome the check was looking for.
- **Evidence is captured, never composed.** A screenshot, a terminal excerpt, or an output offered as proof comes from the running thing and names where — the URL, the fixture, the commit — never a mockup, a synthetic card, or an assembled image.
- **A generated report names the tree it measured.** A handoff, an audit, a sweep — any report that carries counts — carries one line, `Measured-tree: <40-hex>`, a tree hash over the working tree with uncommitted and untracked non-ignored files counted, computed by the `GIT_INDEX_FILE` one-liner `review-changes`' tree-stamp reference owns (`~/.claude/skills/review-changes/references/tree-stamp.md`) — a short head plus "uncommitted changes" cannot say what was measured. A review's instance is `review-changes`' `Reviewed-tree:`, never doubled by this line. Nothing refuses a report without the `Measured-tree:` line; its counts are ones nobody can re-run, and read as `UNVERIFIED:`.
- **`UNVERIFIED:` is for what this session cannot reach.** A claim one read or run away is checked before the sentence is written, and the more irreversible the act the claim feeds, the less room there is to leave it marked. The marker names what would lift it — the command to run, the person to ask, the environment to reach — so the reader is handed the check rather than the doubt.
- **A deferral names where it now lives.** Anything this session set aside — a follow-up, a parked finding, an item noticed and left — is written into the record the work runs from (the plan, the round's register, the ticket, an ADR's `## Deferred`) in the turn that sets it aside, or at latest in the turn that reports the work done, which names that place per item. One whose only home is the transcript or a handoff is `UNVERIFIED:` as uncaptured, and the fix is to write it down: a transcript is not a record, and a handoff is throwaway.
- **A period-scoped summary enumerates the period.** "What I did this week" runs `git log --author=<me> --since=<from> --until=<to> --oneline` and states the window it used — the calendar analogue of the recall check `committing` binds to `<base>..HEAD`.
- **Prose is a first draft.** A report written at the end of long work is a hypothesis about what happened; say so where the evidence is thin rather than letting the register imply certainty.
