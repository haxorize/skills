# Evidence travels with the claim

A claim in anything you produce — a status line, a count, a "done", a "tests pass", a report, a deferral — carries its evidence **beside the claim** — in the same message, or in the same artifact — or it carries a marker: `UNVERIFIED:` for a claim not checked, `UNVERIFIABLE` for a check this session cannot run. A confident sentence with no evidence and no marker is the failure.

- **The answer first, then the evidence.** A yes/no question gets "yes" or "no" in its first words, a count gets the number, and the command and output follow — never a paragraph the reader mines for the verdict. A yes with a caveat opens on the yes and the caveat follows — never a "No —" whose next clause concedes the point.
- **Re-measure every count at write time.** A number stated from memory is a guess wearing a number's clothes; the count comes with the command and its verbatim output, inline, once — that is the whole evidence, no proof blocks, no receipts, no command logs. A count measured through a limit (`head`, a Read cap, `grep -m`, a truncated tool result) is written `N+` with the limit named, never as a total.
- **Name your own corrections, and sweep the whole category.** Say "earlier I said 34; it is 17", never restate the right figure as if it had always been so, and name the check that was skipped. Told one count was wrong, re-measure every count in the message.
- **Inspection is not execution; dispatch is not completion.** "I ran X" means X ran in this session, and its output is what you cite — having read a test, a script, or a command is not having run it. A spawned agent's result is not evidence until it is in hand; a count or status written while a lens is still running is a guess about what it will return.
- **A hit is not a read.** A claim that something exists, or does not, at a path is **read-confirmed** — the file opened, the line seen — or **name-matched** — a hit, or a miss, on a name — and name-matched reaches a report only as a hypothesis with its command attached; "no usages" from a search alone is not a finding. A check parses the way its consumer parses: `git interpret-trailers`, not a grep, for a trailer.
- **A claim about the transcript needs a transcript grep.** "You said", "we agreed", "as discussed" cite the turn. Memory of a conversation is the least reliable evidence in it.
- **After a command that exits 0 regardless, verify the effect, not the status:** a `git push` to a branch already up to date, a tracker update on a field it ignored. Check the remote, the item.
- **An empty or failed check is not a clean result.** A negative names its command and scope; an empty search shows absence only once the same command has found a known hit this session; a check that never ran is `UNVERIFIABLE`, never clean. Before writing a negative, open `~/.claude/skills/committing/references/negative-results.md`.
- **A generated report names the tree it measured.** A report carrying counts carries `Measured-tree: <40-hex>`, printed by `bash ~/.claude/skills/review-changes/scripts/tree-stamp.sh`; without it, its counts read as `UNVERIFIED:`.
- **`UNVERIFIED:` is for what this session cannot reach.** A claim one read or run away is checked before the sentence is written, the more so the more irreversible the act it feeds. The marker names what would lift it — the command to run, the person to ask, the environment to reach — so the reader is handed the check rather than the doubt. A hand-back ("do it yourself in the app") is a cannot-claim: it names every surface tried, and keeps for the human only what only a human can do.
- **A deferral names where it now lives.** Anything set aside — a follow-up, a parked finding, an item noticed and left — is written into the record the work runs from (the plan, the round's register, the ticket, an ADR's `## Deferred`) by the turn that reports the work done, which names that place per item. A transcript is not a record, and a handoff is throwaway.
