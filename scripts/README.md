# Conventions for `scripts/`, `scripts/git-hooks/`, `.claude/skills/*/scripts/` and `src/*/scripts/`

This file holds only rules that bind more than one gate. A rule about one script lives in that script's header, and its check roster, scope, and exit codes in its `--help`; why a gate exists goes to an ADR.

## Run the selftest of what you touched

Every `scripts/<name>.sh` and `scripts/git-hooks/<name>` that is not a selftest, a `*-lib.sh`, or `setup-hooks.sh` has a `<name>-selftest.sh` beside it. One name is exempt, `setup-hooks.sh`, because it writes into `.git/hooks` and has no readable surface to grade without a throwaway clone; everything else here is gradeable against a fixture or a redirected `HOME`. `lint-skills.sh` fails one that lacks it — a git hook is any file under `scripts/git-hooks/` whose first line is a shebang, and it must itself be executable — and `post-merge` derives its gate roster from the pairing, so a script is gated the moment its selftest exists. A third walk covers `.claude/skills/*/scripts/` on the same pairing contract, so a skill-private script owes a selftest and `lint-skills.sh` fails one that lacks it. It is not *gated* in the sense above: `post-merge`'s roster is built from `scripts/*-selftest.sh`, `scripts/git-hooks/*-selftest.sh` and the `# Install note:`-marked hooks under `global/hooks/`, and `pre-commit`'s selftest map has no `.claude/` arm — so nothing runs a skill-private selftest on merge or commit. What reaches it is the lint pairing check, which grades existence, plus `sweep-corpus`'s hand-run gate loop. A fourth walk covers a shipped skill's bundled scripts under `src/*/scripts/` ([ADR-0103](../docs/adr/0103-bundle-deterministic-skill-logic-as-a-tested-script.md); the walk is [ADR-0104](../docs/adr/0104-triage-cvits-is-the-second-bundled-script-lint-gap-deferred-again.md)'s 2026-10-10 amendment) on the same pairing contract, for `*.sh` and `*.py` alike: `foo.py` pairs with `foo-selftest.sh` beside it, and the walk goes one level deep, so a selftest's `<stem>-fixtures/` directory is data and is never held to the pairing. Unlike the `.claude/` tree, `pre-commit` queues these selftests: a staged `src/*/scripts/foo.{sh,py}` or a file in its `foo-fixtures/` runs `foo-selftest.sh`, and a staged `scripts/*-lib.sh` runs them with the rest. `post-merge` runs them on every merge and `sweep-corpus`' gate loop reads them too. Every file the walks visit opens with `# Conventions for this tree: scripts/README.md` — line 2 after a shebang, line 1 in a sourced library — and `lint-skills.sh` fails one that does not. That path is relative to the repo root, not to the file carrying it, which is what lets one literal serve all four trees; resolve it from the checkout root rather than from the script's own directory. `dev/` is outside every walk above: its scripts are hand-run, carry no selftest, and no hook or lint reads them.

- After changing a script or hook, run its `-selftest.sh`.
- After changing a check in `lint-skills.sh` or `lint-adrs.sh`, run that linter's selftest: a lint gate that quietly stopped matching looks identical to a repo with no violations. Each selftest's header names what it grades and what it does not, and that list is the authority.
- After touching `scripts/selftest-lib.sh`, run every `scripts/*-selftest.sh`, every `scripts/git-hooks/*-selftest.sh` and every `src/*/scripts/*-selftest.sh` — each sources it — and every `global/hooks/` selftest that names it (`grep -l scripts/selftest-lib.sh global/hooks/*-selftest.sh`), whose mutation table sources it for `selftest_mutate` and `selftest_expect_killed`.
- Between edits, `lint-skills.sh --files <path>…` grades just the named files in about a second; a clean run prints `lint-skills.sh PARTIAL:` and exits 2, since the whole-tree checks (the shared trigger phrase, pass 3, the byte totals) did not run, so it never stands in for the full run before a commit.
- After touching `scripts/lint-lib.sh`, run `lint-skills-selftest.sh` and `lint-adrs-selftest.sh` before committing — both linters source it for `say_fail` and the failure flag. When any `scripts/*-lib.sh` is staged, `pre-commit` runs every selftest under `scripts/` and `src/*/scripts/`, plus each `global/hooks/` selftest that names the lib's path, never one under `.claude/skills/*/scripts/` (its `Gate map:` lines are the rule); that is the commit gate, not the edit-time check.
- A file no gate walks is gated only by the selftest that runs it: touch such a file, run that selftest.

`selftest-lib.sh`'s header defines a selftest's three outcomes and what each exit status means.

## The exit-code taxonomy

Every script under `scripts/`, every hook under `scripts/git-hooks/`, every hook selftest under `global/hooks/`, every skill-private script under `.claude/skills/*/scripts/`, and every skill-bundled script under `src/*/scripts/`, Python included, renders one of five statuses, and `DOMAIN.md` registers them under this name (`sweep-corpus` reads `exit=` off all five trees):

- **0** — clean.
- **1** — at least one `FAIL`.
- **2** — nothing, or not everything, was checked: a linter over an empty tree, a clean `lint-skills.sh --files` run (the whole-tree checks skipped), a selftest that left a branch unexercised or stopped after its passing rows at a missing temp directory (`SELFTEST PARTIAL`), a `skill-usage.sh` count carrying a `+` floor.
- **3** — usage error.
- **4** — a check never ran, so the run is not a verdict on anything: the script is broken, or the environment it needs is (an unwritable `TMPDIR` under the failure flag, say). Either fault is a different claim from the corpus being wrong.

Two exceptions, each stated in its script's `--help`. `security.sh` spends 4 on its `--fail-on` threshold, which callers gate on, so its never-ran cases (no temp file, a `--path` that is not a directory) exit 2. `work-item-shape`'s `tracker.py` exits 5 when a write landed but its read-back or link did not, because its caller must not treat that write as one that never landed (1) and re-run the create.

A `WARN` never moves the status. `scripts/git-hooks/post-merge` and `sweep-corpus` read the number alone, so the 2 is what tells a narrower clean from a whole one. A script states its own roster in `--help`; it does not restate this table. [ADR-0068](../docs/adr/0068-lint-adrs-enforces-two-way-pointers.md) set 0-3 and [ADR-0072](../docs/adr/0072-shared-trigger-phrase-check-and-never-ran-is-not-clean.md) added 4.

## Temp files take a full-path template

`mktemp` takes `"${TMPDIR:-/tmp}/<name>.XXXXXX"` (with `-d` for a directory), never the bare form and never `-t`: on Darwin both ignore `TMPDIR`, so they fail where `TMPDIR` is the only writable temp path. The guard tests the assignment itself, `if ! x=$(mktemp …) || [ ! -f "$x" ]; then …`, never the variable on the next line — under `set -e` a failing command substitution in a bare assignment exits before that line runs, silently. The failure message names the template and `TMPDIR`, as `lint-lib.sh`'s does, and the status is the taxonomy's 4 — for a selftest too, when no row ran yet; `selftest-lib.sh`'s `selftest_no_tmpdir` is that close, and its header says how it reports a guard reached after rows already ran (1 if one failed, `SELFTEST PARTIAL` and 2 if all passed). Each site carries a one-line pointer here rather than the reasoning.

## A check lands with its fixture and its mutation, in both directions

The `Why not a hook or lint:` line the `scripts/lint-fixtures*/global/rules/*.md` fixtures carry is **inert filler** — no check parses it (`grep -c 'Why not a hook' scripts/lint-skills.sh` → 0), and the real rule files stopped carrying it on 2026-08-31, when the control moved into [ADR-0053](../docs/adr/0053-global-rules-layer.md) § Admission rule. Each fixture's line says what that fixture is for, which is why it stays; do not copy the key into a new rule file.

A new or edited check in any `scripts/*.sh` gate, and a hook under `global/hooks/`, lands with a fixture instance that fires and a mutation that reds its selftest, both ways. Narrowing: an alternative dropped from the pattern, and the instance that stops firing turns the selftest red. Widening: a boundary loosened, and the clean neighbor that starts firing turns it red. So a fixture carries one graded instance per alternative, not one per rule, and the selftest carries the mutation table. A hook selftest's mutation table edits a copy of the hook and requires every mutant to flip its row, through `selftest-lib.sh`'s `selftest_mutate` (a pattern no longer in the file fails by name) and `selftest_expect_killed` (one row per mutant), as every mutation table under `scripts/git-hooks/` does too; which hook selftests carry one is `grep -l '^mutant\|mutation table' global/hooks/*-selftest.sh`. The selftest-pairing check proves a selftest exists, never that it can fail — `security-selftest.sh` graded one instance per rule until 2026-08-29, and cutting `_DROP_HOSTS` from twenty-odd host patterns to one left it green. What can cover the gap mechanically, when a person runs it, is `scripts/mutation-sweep.sh` (nothing schedules it — `sweep-corpus`'s gate loop does not run it): it derives the same roster as `post-merge` plus the libraries, generates one-line mutants of each script (`mutation-sweep.py`'s three operators), runs the paired selftest over each on a copy of the tree, and names every site the selftest stayed green over as SILENT. It is hand-run, not a gate — a full pass costs one selftest run per mutant — so its header sets the cap and the single-target mode, and [ADR-0093](../docs/adr/0093-mutation-sweep-over-the-gates.md) records its first run. A hand-written mutation row still lands with a check; the sweep is the audit that the table is not the only thing holding the selftest honest.

**A rule tightened over existing bodies pins today's violators, and the pin only shrinks.** When a new check would fail files already in the tree, list those violators in the check's selftest as a closed baseline, and fail the selftest when the list grows or changes; fixing a violator shortens the list in the same change. `security-selftest.sh`'s `retro_pinned` is the form: `src/retro`'s findings are pinned by rule, file and count, and any other result, a new finding included, reds the selftest. An open "known exceptions" note lets the next violation in unseen; a pinned list makes every addition a red selftest.

## Landing a change here

`Review required: yes` in `CLAUDE.md`'s `Landing:` block arms the `review-receipt` hook under `global/hooks/` once it is wired in `~/.claude/settings.json` (`bash scripts/install.sh` prints the snippet): a push needs a `/review-changes` report whose `Reviewed-tree:` stamp equals the tree being pushed, and `/address-findings` re-stamps after its fix pass. Any edit after the last stamp needs a new one; the order, and the next act for the tree as it stands, is what `src/committing/scripts/next-step.sh` prints. The `pre-commit` git hook runs `lint-skills.sh` and `lint-adrs.sh` on the paths a commit touches, runs the selftest of each staged `scripts/` script, git hook or `src/*/scripts/` script, or of the script whose `<stem>-fixtures/` file is staged (every selftest in those three places, and each hook selftest naming it, when a `scripts/*-lib.sh` is staged; a staged `.claude/skills/*/scripts/` script runs none), and the hook selftests a staged `global/hooks/` file or `src/*/scripts/` script reaches (its gate map says which); `commit-msg` checks message shape and never register, so `src/committing/references/commit-style.md` is not pruned against it.
